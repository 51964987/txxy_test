一、功能概述

「分享」是本项目把本地 downloads/ 中的媒体资源以链接形式对外（主要是局域网）展示的能力，核心特征是：

  • 支持单文件分享，也支持一次性分享整个目录 / 勾选的多个文件（一个链接对应一组文件）；
  • 分享页为画廊式只读预览（图片/视频内联预览，不含下载按钮），有效期可选 1h / 24h / 7d / 30d；
  • 由运行在独立端口（默认 8090）的独立服务进程承载，与主看板（8088）完全隔离；
  • 分享索引 outputs/share_index.json 由主应用写入、分享服务只读。

用户入口：资源管理「浏览」抽屉标题栏的「分享此目录」（经类型/名称筛选后的全部文件）、卡片/行内「分享」（单文件）。

二、总体架构：端口隔离的独立服务

分享服务是一个单独的 FastAPI 应用 share_app（定义在 web/share.py），由 web/share_server.py 作为进程入口用 uvicorn 拉起，监听 SHARE_PORT（默认 8090）。它不挂载任何前端 SPA 静态资源，/ 也不返回看板。

主看板 8088（FastAPI SPA） → POST /api/share 写 share_index.json → 独立分享服务 8090（仅 /share/*） → 访客只读画廊预览

这样设计的收益是「最小暴露面」：分享链接落到 8090 端口，天然拿不到 8088 的管理界面（帖子、下载任务、回收站等），即便链接被他人获取，也只暴露被显式选中的那一组文件。

业界对照：大型网盘（Google Drive、Dropbox、百度网盘）的「分享页」同样是独立域名/独立服务，与登录态的管理后台隔离，避免分享链接成为越权入口。本项目的「独立端口」是单机自用的轻量等价实现。

三、分享模型：一个 token → 一组文件

创建分享的入口是 create_share(rel_paths, ttl)：它把多个 downloads/ 内相对路径合并为一个分享链接。核心数据只有三项：

  • token：链接唯一标识；
  • rels：相对路径列表（一组文件）；
  • expire_at：过期时间戳。

创建时对每个 rel 做规范化（反斜杠归一、去首尾斜杠）并调用 resources.resolve_safe 校验存在性，任一文件越界或不存在则整体失败（FileNotFoundError）。标题取所有路径的「最深公共目录」_common_dir（如 a/b/c.jpg 与 a/b/d.jpg → a/b）。

业界对照：这正是网盘「分享文件夹 / 多选分享」的同思路——把若干对象打包成一个分享实体，统一管控过期与撤销，而非为每文件各生成一个链接（后者难以批量失效、索引易膨胀）。参考 AWS S3「用一个 presigned URL 共享一个对象或一组带前缀的对象」、百度网盘「分享整个文件夹」。

四、分享索引与原子写

索引文件 outputs/share_index.json 的结构为：

{
  "items": [
    { "token": "...", "rels": ["a/b.jpg", "a/c.mp4"],
      "ttl": "7d", "created_at": 1234567890.0, "expire_at": 1235172090.0 }
  ]
}

写入采用原子替换：先写临时文件 share_index.json.tmp，再 os.replace 落到正式路径；读取方（分享服务）无锁读取也始终看到完整文件，不会读到半截。

def _save(data):
    tmp = INDEX_FILE.with_suffix(".json.tmp")
    with open(tmp, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
    os.replace(tmp, INDEX_FILE)   # 原子替换：要么旧、要么新，无中间态

因主应用与分享服务是两个进程，写索引还要加跨进程排他锁：用 os.open(LOCK_FILE, O_CREAT | O_EXCL) 创建锁文件实现忙等（超时 5s），保证并发创建分享时索引不互相覆盖。

业界对照：「写临时文件 + rename 原子替换」是 POSIX/业界标准的安全写文件模式（DB 引擎、配置热更新通用），可避免进程崩溃/并发读写导致的文件损坏。跨进程的 O_EXCL 锁是单用户场景下最轻量且可靠的互斥手段。

五、路径安全：防穿越

分享涉及把「外部传入的相对路径」解析为磁盘真实文件并返回，路径穿越（Path Traversal / Directory Traversal）是首要风险：攻击者若能用 ../../etc/passwd 之类路径读到 downloads/ 之外的文件，即造成信息泄露（CWE-22）。

本项目用 resources.resolve_safe(rel) 兜底：把相对路径限定解析到 downloads/ 根目录、并校验最终落点确实位于 downloads 内且为已存在文件；创建时校验一次，访问时（resolve_token、inline_file）再校验一次。

def resolve_safe(rel):
    target = _resolve_within(rel)          # 解析到 downloads/ 内并校验前缀
    return target if target is not None and target.is_file() else None

注意 resolve_token 在任一文件已被删除时整体返回 None → 链接 410（见下一节），即「文件没了，分享也失效」，不会泄露「哪些文件存在」之外的额外信息。

业界对照：OWASP 将路径遍历列为高频攻击（Path Traversal - OWASP）。通用防御有两条：(1) 对用户输入做白名单/规范化，绝不直接拼接进文件系统路径；(2) 解析后用「真实绝对路径是否仍在允许根目录内」做前缀校验。本项目 _resolve_within + resolve_safe 正是该思路的落地。

六、不可猜测的随机 token

token 用 secrets.token_urlsafe(16) 生成，约 128-bit 随机、URL 安全。它不是顺序自增 ID，因此访客无法靠「猜下一个号」枚举他人分享。

token = secrets.token_urlsafe(16)   # 约 128-bit 熵，暴力枚举不可行
业界对照：AWS S3 预签名 URL（presigned URL）本质就是一段带签名/随机串的临时授权链接（Using presigned URLs - Amazon S3）；主流网盘分享码同样是随机不可枚举。核心原则一致：授权靠「链接本身的不可猜测性」，而非靠隐藏的 ID 空间。

七、有效期 TTL 与 410 Gone

可选档位 TTL_HOURS = {"1h":1, "24h":24, "7d":168, "30d":720}，默认 7d。expire_at = now + 小时数×3600。

resolve_token 在两种情况下返回 None（视为链接失效）：

  • expire_at < now：已过期；
  • 任一文件已被删除（resolve_safe 返回 None）。

返回 None 时接口抛 HTTPException(410, "分享链接已过期或不存在")。用 410 而非 404，是因为 410（Gone）语义是「曾经存在、现已永久移除」，比 404（未找到，可能从未存在）更准确地描述「该分享已失效」。

业界对照：HTTP 410 在 RFC 9110 中用于标记「资源曾存在但已被有意移除」，常用于限时资源/失效邀请。S3 presigned URL 过期后也会返回拒绝（403/失效），本质同属「限时授权 + 到期即废」。参考 410 Gone - MDN。

八、分享服务路由

分享服务仅暴露两条路由（均不依赖前端 SPA）：

方法 / 路径作用关键实现
GET /share/{token} 画廊式预览页（目录名 + 文件网格 + 查看器 + 缩略图条） 返回 HTMLResponse，Cache-Control: no-store（动态模板，禁缓存确保改版即时生效）；resolve_token 失败则 410
GET /share/{token}/file?i=N 内联返回第 N 个文件（图片/视频浏览器预览） FileResponse(..., content_disposition_type="inline")；序号越界 404、文件已删 410；Starlette 原生支持 Range，视频可拖动进度条
GET /health 健康检查 返回 {"ok": true, "service": "share"}
业界对照：视频拖动进度条依赖 HTTP Range 请求与 206 Partial Content（HTTP 范围请求 - MDN）。Starlette 的 FileResponse 对 If-Range/Range 原生支持 206，无需手动分片，是流式播放的标准做法。

九、画廊页与沉浸式查看器

预览页由 _render_gallery 用一份 HTML 模板（_GALLERY_TPL占位符替换生成（__TITLE__、__TOKEN__、__GRID__ …），刻意不用 f-string，避免与 CSS/JS 里的大量 { } 冲突。前端交互借鉴图片集合浏览的通行做法：

① 类型筛选 + 名称搜索 + 前端分页

  • 顶部工具栏：全部图片视频文本种子其他 + 文件名搜索；
  • 前端分页每页 60 条、窗口化页码，筛选/搜索变化自动回第 1 页。

② 沉浸式 1:1 滑动查看器（Lightbox）

  • 全屏黑底，每屏一张；图片 object-fit: contain 且支持滚轮/双指捏合/双击缩放与平移，视频默认最大化填充且打开即自动播放；
  • 手指/鼠标跟手横滑翻页，松手按位移阈值吸附到相邻页；下滑或 Esc 退出；
  • 顶栏与底部缩略图条自动隐藏、交互时浮现。

③ 底部缩略图条（Filmstrip）

  • 横滑浏览「筛选后」的文件，与网格口径一致（翻页不会跳到非筛选类型）；当前项高亮，点击即跳转；
  • 视频缩略图取首帧展示（进入视口才懒加载，避免裸 <video> 黑屏）：桌面端 seek 到 5% 取代表帧，移动端/iOS 走「静音播放 → playing 取帧」可靠路径；
  • 媒体按「当前 ±2」窗口懒加载，切换/关闭时自动暂停后台视频（避免切到图片仍出声）。
业界对照：
  • 沉浸式看图/滑动翻页：PhotoSwipe、Google 相册、iOS 照片的通用形态；
  • 视频首帧 poster：YouTube / Netflix / Vimeo 均用服务端抽帧做封面，绝不渲染「无 poster 的裸 video」（即黑屏）；本项目用 canvas drawImage 在客户端取首帧，是「无服务端抽帧」下的等价兜底；
  • 窗口化懒加载（仅渲染可视邻域）：YouTube / Netflix 无限滑动与无限列表的标准性能手段，避免一次性建几百个媒体节点导致内存/请求风暴。

设计取舍：画廊页不含下载按钮，定位为「只读预览」而非分发源——降低分享链接被当作公开下载站的滥用风险（仍是本机/局域网内、配合随机 token 与过期时间使用）。

十、分享链接基址

生成链接的基址由 _share_base(request) 构造，端口恒为独立分享端口 SHARE_PORT，确保链接落到隔离的分享服务而非 8088 看板。主机名优先级：

  1. 页内「参数设置 → 分享链接」share_host（如局域网 IP 192.168.1.5）；
  2. 回落到环境变量 TXXY_SHARE_HOST；
  3. 再回落到请求 Host 的主机（自动适配局域网 IP / 域名）；
  4. 最后兜底 config.HOST。

这样无论用 localhost 还是域名访问看板，生成的链接都可固定指向本机 IP，便于局域网他人直接打开；同时要求把 TXXY_WEB_HOST 设为 0.0.0.0 让分享服务监听所有网卡。

十一、创建限流

创建分享接口挂在限流依赖 ShareRateLimit = rate_limit(20, 60)（固定窗口，60 秒内最多 20 次）。目的是防止分享接口被刷——既避免无意义的索引膨胀，也避免被当作遍历/探测 downloads/ 的入口。

业界对照：任何「可被外部触发写操作 / 生成资源」的接口都应有限流（如网盘创建分享的频率限制、S3 presigned URL 的签发配额），是防 DoS 与防滥用的基础手段（本项目统一限流实现见 web/ratelimit.py）。
