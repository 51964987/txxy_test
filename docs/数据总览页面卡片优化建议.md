## 二、业务角色与关注点

| 角色 | 核心诉求 | 当前页面满足度 |
| --- | --- | --- |
| 内容运营/版主 | 内容量是否健康、哪些版块热/冷、热门内容在哪 | 基本满足 |
| 数据分析/决策者 | 趋势是否正常、有无异常波动、环比对比 | 部分满足（缺周同比、异常提示） |
| 爬虫/数据维护者 | 抓取是否正常、数据是否新鲜、哪些版块断更 | **不满足**（页面无任何抓取/新鲜度信息） |
| 普通浏览者 | 最新内容、热门内容快速入口 | 部分满足（热门榜不可点击跳转详情） |

## 三、问题诊断（从角色视角）

1. **运维角色完全缺位**：页面没有任何「数据新鲜度/抓取状态」指标。数据断了 3 天，总览页看起来「一切正常」——这违背看板「一眼确认系统健康」的第一原则。
2. **「累计用户」口径误导**：`total_users` 实际是「去重发帖作者」，`活跃率 = 今日作者 / 累计作者`。对论坛场景，「用户」容易被误读为注册用户数，且活跃率受抓取节奏影响大（非独立指标）。
3. **信息重复**：
   - 「近 7 日新增」KPI 与「总版块趋势图（7 天档）」高度重复；
   - 「环形图」与「排行榜」完全同源（同一份 `fid_dist`），且当前版块数（10+）超出饼图类目 5~6 个的最佳实践，可读性差。
4. **「谷值」业务价值低**：趋势图头部统计条展示谷值，运营和决策者几乎不关注「最低值」，关注的是峰值与均值（互联网看板惯例：趋势区展示峰值/均值即可）。
5. **缺「行动/异常提示」**：看板最佳实践要求「不只是展示结果，还要提示该做什么」。当前无「今日 0 新增版块」「近 7 日持续下滑」等提示。
6. **热门榜仅 2 栏且不可下钻**：点赞/回复 Top 帖子没有跳转帖子列表详情；「今日最热」在运营场景比「历史累计最高」更常用。
7. **无内容质量维度**：没有「平均点赞/回复」这类反映内容质量与社区互动度的指标。

## 五、建议新增（5 项）

### A-01 数据新鲜度 KPI（P0，前端 only，零后端成本）
- **面向角色**：爬虫/数据维护者、决策者
- **内容**：最新数据日期 + 距今天数（如「数据截至 08-25 · 已滞后 1 天」），或并入「累计帖子」卡副信息。
- **数据支撑**：`/stats/overview` 已有 `latest_date`、`latest_created_at`，前端直接计算，无需后端改动。
- **参考依据**：数据看板通用原则——「刷新状态/数据时间戳」是必选项，避免用户基于过期数据做决策。

### A-02 异常版块提醒卡（P0，前端 only，零后端成本）
- **面向角色**：爬虫维护者、内容运营
- **内容**：列出「今日 0 新增」「近 7 日 0 新增」「最久未更新」的版块（红/黄提示）。
- **数据支撑**：`/stats/fid_dist` 已有 `today_count`、`yesterday_count`、`latest_date`，前端筛选即可。
- **参考依据**：异常清单（Anomaly/Alert List）是运维看板标配，把「需要人处理的事」前置。

### A-03 周同比 / 7 日环比（P0，前端 only，复用 trend 接口）
- **面向角色**：数据分析/决策者
- **内容**：「今日新增」KPI 卡副指标增加「较 7 日日均」；趋势图可叠加「上周同期」参考线。
- **数据支撑**：复用 `/stats/trend?days=14`，前端切片对比即可（今日 vs 7 日日均、本周 vs 上周）。
- **参考依据**：KPI 卡片最佳实践——「核心数字 + 趋势指示 + 对比参照」三要素。

### A-04 活跃作者榜 Top10（P1，需后端小接口）
- **面向角色**：内容运营
- **内容**：近 7 日 / 累计发帖最多的作者（KOL 识别），点击可跳转该作者帖子。
- **数据支撑**：`posts` 表已有 `author` 字段，后端新增 `GROUP BY author` 接口即可（参照现有 `db.cached` 模式）。
- **说明**：社区类看板「活跃作者」是常见指标；可与热门榜共用一行。

### A-05 今日热议 / 今日新增版块 Top（P1，需后端小接口）
- **面向角色**：内容运营、浏览者
- **内容**：热门榜扩为 4 栏：点赞最高 / 回复最高 / **今日最热（今日按点赞+回复综合）** / **今日新增版块 Top**；并支持点击跳转帖子列表。
- **数据支撑**：后端新增 `/stats/today_top`（按 `date=today` 过滤排序）与 `/stats/today_fids`（今日新增前 N 版块）。文档中曾声称实现过，实际已不存在，需重新落地。
- **说明**：若不想动后端，可用前端 `posts({ sort })` 现成接口替代「今日最热」，成本更低。
