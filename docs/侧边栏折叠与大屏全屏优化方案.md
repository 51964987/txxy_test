# 侧边栏折叠 / 移动端适配 / 大屏全屏 优化方案（待确认）

> 状态：**已实施**（2026-08-30）。三项决策已确认：① 全屏对象 = 右侧内容区 ② 全屏态轮询保持 5s ③ 移动端断点 768px。
> 涉及范围：仅前端 `web/frontend/src`，未新增依赖、未改后端接口、未改既有 5 条路由路径与 history 模式。
> 实施过程中与原方案的差异、实测验证结果见第 10 节「落地说明」。

---

## 1. 背景与目标

现有布局为「固定侧边栏 + 顶部 Header + 内容区」三段式，实测与代码审查发现：侧边栏无法折叠、无移动端适配、数据总览缺少大屏展示能力。本次目标：

| 编号 | 需求 | 目标 |
|---|---|---|
| R1 | 左侧菜单支持折叠/展开，兼容桌面端与移动端 | 桌面可收成图标条腾出内容宽度；移动端不挤占屏幕 |
| R2 | 数据总览保留实时时钟、自动刷新等现有能力 | 功能不回退，且在折叠/全屏/移动场景下依然可用可见 |
| R3 | 评估是否新增「全屏」按钮，使总览进入浏览器全屏 | 给出是否做、做哪种、风险与替代方案的结论 |

## 3. 现状问题（按严重程度）

### 高

1. **侧边栏完全不可折叠，也不可隐藏**：212px 在 1366×768 笔记本、横屏平板、手机上直接吃掉 15%~30% 宽度；内容区被压缩后 `stat-grid` 于 1100px 断点降级为 2 列，出现「页面才切两列右侧却空着一大条」的割裂观感。
2. **移动端基本不可用**：侧栏常驻 + Header（标题 + 时钟 + 自动刷新卡片）在 <768px 时横向挤压，`el-header` 无换行/无隐藏策略，360~414px 宽度下必然溢出或挤压变形。
3. **折叠/全屏后 ECharts 不会 resize（潜在必现错位）**：`DashboardView` 只监听 `window.resize`。侧栏折叠、抽屉开合、进入全屏**都不触发 window resize**（或触发时机早于布局完成），图表 canvas 尺寸将停留在旧值，表现为「图表被裁切 / 留白 / 坐标错位」。

### 中

4. **Header 控件无响应式降级**：时钟为 `YYYY-MM-DD HH:mm:ss` 共 19 字符，窄屏下与自动刷新卡片、标题三者争抢空间，无优先级取舍规则。
5. **缺少大屏展示能力**：数据总览已是 KPI + 多图表的典型看板结构，但图表高度写死 320px，投屏到 1080p/2K 时下半屏大片留白，不具备投屏/值班大屏价值。
6. **菜单硬编码**：5 项菜单写在模板里，未来若做折叠态 tooltip 或权限控制，需要改多处（与本次改动范围重叠，可顺势收敛）。

### 低

7. `useAppStore` 空置，跨页 UI 状态（折叠态、全屏态）无处安放，容易被误建成第四个 store。
8. 菜单项折叠后无文字提示（Element Plus 折叠态不自带 tooltip），需补交互。

## 4. 优化建议

### 4.1 R1 侧边栏折叠（推荐「桌面图标折叠 + 移动抽屉」双态）

- **桌面端（≥768px）**：`el-menu` 加 `:collapse`，折叠后 aside 宽度 212px → 64px，仅保留图标；折叠态为菜单项补 `el-tooltip`（`placement="right"`）显示名称，避免「只有图标看不懂」。触发按钮放在 Header 最左侧（汉堡图标），与主流后台一致。
- **移动端（<768px）**：侧边栏默认隐藏，改为 `el-drawer` 抽屉（`direction="ltr"`、`size="212px"`、带遮罩），点击菜单项后自动关闭抽屉。
- **菜单复用**：抽出 `layout/SideMenu.vue`，内部只渲染 `el-menu`（去掉外层容器），桌面 aside 与移动 drawer 各包一层容器共用同一组件，杜绝两份菜单不同步。
- **菜单数据化**：把 5 个菜单项抽成 `MENU_ITEMS` 常量（`{ path, title, icon }`），模板 `v-for` 渲染。与现有路由一一对应，不新增/不改动路由。

### 4.2 R2 保留并强化现有能力

- 实时时钟 `nowText`、自动刷新 `el-switch`、`/api/config` 驱动逻辑**一行不改**，仅调整 Header 布局与窄屏可见性：
  - ≥768px：维持现状（标题 + 时钟 + 自动刷新卡片）。
  - <768px：隐藏时钟的**日期部分**（仅留 `HH:mm:ss`）、自动刷新卡片仅留图标+开关（隐藏"自动刷新"文字），保证不溢出。时钟/开关本身**不隐藏**，满足 R2。
- 轮询 5s、5s TTL 缓存等既有口径保持不变（不回退为 30s）。

### 4.3 R3 全屏按钮评估（结论：建议做，采用「真全屏 + CSS 伪全屏降级」）

**是否值得做：值得。** 理由：

- 数据总览已经是看板形态（4 KPI + 趋势 + 分版块对比 + 双 Top10 + 4 个榜单），信息密度足以支撑投屏。
- 用户按 F11 让整个浏览器全屏时，侧栏与 Header 依旧占位，观感并不"大屏"；而按钮式全屏可以做到「只让数据区铺满屏幕」。
- 成本可控：核心是 Fullscreen API + 一个全屏态 CSS 变量，不引入第三方库。

**关键取舍：全屏对象选谁？** 建议对**右侧内容区容器**（`el-container.body`，即 Header + Main）调用 `requestFullscreen`，而不是整个 `documentElement`，也不是 `el-main`：

- 对 `el-main` 全屏 → Header 被裁掉，时钟与自动刷新消失，**违反 R2**；
- 对 `documentElement` 全屏 → 侧栏仍在，且等价于 F11，按钮失去意义；
- 对 `.body` 全屏 → 侧栏天然不在全屏元素内（自动隐藏），**Header 时钟与自动刷新开关保留**，同时新增「退出全屏」图标按钮，完全满足 R2 + R3。

## 5. 实现思路

### 5.1 状态归口：`stores/app.ts`（复用空置 store，不新建）

```ts
// 仅示意，非最终代码
isMobile: boolean            // 由 matchMedia('(max-width: 767px)') 维护
collapsed: boolean           // 桌面折叠态（持久化到 localStorage）
drawerVisible: boolean       // 移动端抽屉开合（瞬时态，不持久化）
fullscreen: boolean          // 当前是否处于大屏全屏
layoutResizeKey: number      // 布局尺寸变化版本号，供图表订阅
```

- 断点判定用 `window.matchMedia('(max-width: 767px)')` + `change` 监听，**不用** `window.innerWidth + resize`（避免与图表 resize 抢事件、避免高频抖动）。
- 持久化手写 `localStorage`（键如 `txxy.aside.collapsed`），**不引入** `pinia-plugin-persistedstate` 等新依赖。
- 移动端自动视为"折叠"，桌面/移动切换时重置抽屉状态，避免出现"桌面折叠 + 移动抽屉同时开"的脏状态。

### 5.2 布局改造：`layout/AppLayout.vue`

- `el-aside` 宽度改为动态：`:width="isMobile ? '0px' : (collapsed ? '64px' : '212px')"`；移动端用 `v-if` 直接不渲染 aside，改渲染 `el-drawer`。
- `el-menu` 加 `:collapse="!isMobile && collapsed"`、`:collapse-transition="false"`（关掉 EP 默认 0.3s 宽度动画，避免与 ECharts resize 抢帧造成抖动）。
- Header 最左侧新增折叠/菜单按钮：移动端为 `Fold/Expand` 汉堡（开抽屉），桌面为 `Expand/Fold` 图标（切折叠）。
- Header 右侧新增全屏按钮：仅 `route.path === '/'`（数据总览）时显示，图标 `FullScreen`/`Aim`，tooltip 提示「进入大屏 / 退出全屏（Esc）」。
- **全屏按钮只对 `/` 显示**，其余 4 个页面不做全屏（避免表格页全屏后分页/弹窗行为复杂化）。

### 5.3 图表自适应：把 `window.resize` 换成 `ResizeObserver`（**本次改动的关键前提**）

现状 `DashboardView.vue:599` 只监听 `window.resize`，无法覆盖折叠/抽屉/全屏三种尺寸变化。建议：

- 在 `DashboardView` 用 `ResizeObserver` 观察页面根容器，`debounce ~120ms` 后统一 `chart.resize()`（趋势图、分版块图、作者图、版块图共 4 个实例）；
- 保留 `window.resize` 监听作为兜底或直接移除（ResizeObserver 已完全覆盖）；
- 折叠态切换、全屏切换后在 `nextTick` 主动触发一次 resize，避免动画期间尺寸未定。

> 说明：也可以让 store 的 `layoutResizeKey` 自增、页面 `watch` 它来 resize。但 `ResizeObserver` 更通用，能同时吃掉「侧栏折叠动画、抽屉、全屏、窗口缩放、滚动条出现」五种场景，推荐前者。

### 5.4 全屏实现（`Fullscreen API` + 伪全屏降级）

```ts
// 仅示意流程
async function toggleFullscreen() {
  const el = bodyRef.value!                       // 右侧内容区容器
  if (document.fullscreenElement) { await document.exitFullscreen(); return }
  if (el.requestFullscreen) await el.requestFullscreen()
  else enterPseudoFullscreen()                    // 降级：CSS 伪全屏
}
document.addEventListener('fullscreenchange', syncFullscreenState)
```

- **状态同步必须监听 `fullscreenchange`**：用户按 `Esc` / `F11` 退出时，按钮图标与 store 状态需同步回 `false`，否则会"点击无效"。
- **降级路径（CSS 伪全屏）**：`position: fixed; inset: 0; z-index: 1000; background: var(--app-bg)`，逻辑与真全屏共用同一套 `fullscreen` 状态与样式变量。覆盖 **iOS Safari / 旧版 Safari**（元素级 `requestFullscreen` 支持不全）与 iframe 未授权场景。
- 退出入口要冗余：按钮、Esc、以及全屏态 Header 的常驻退出图标。

### 5.5 大屏密度：全屏态 + CSS 变量放大（不做等比缩放）

全屏态时给容器加 class `is-fullscreen`，通过 CSS 变量覆盖关键尺寸，解决「1080p 下半屏留白」：

```css
/* 仅示意 */
.dashboard { --chart-h: 320px; --stat-value: 26px; }
.dashboard.is-fullscreen {
  --chart-h: calc((100vh - 260px) / 2);   /* 两行图表 + KPI 铺满一屏 */
  --stat-value: 34px;
}
.chart-wrap, .trend-chart-wrap { height: var(--chart-h); }
```

- 全屏态下内容区改为**不滚动**（一屏展示完），`el-main` 溢出由 grid 行高吸收；
- 榜单 `.board-list` 的 `max-height: 360px` 在全屏态放开为 `calc(var(--chart-h) - 40px)`，让 4 个榜单与图表等高对齐。

### 5.6 全屏时必须处理的「弹层挂载」问题（最高技术风险，务必纳入）

进入真全屏后，**只有全屏元素及其后代会被渲染**，挂在 `body` 上的弹层会"消失"：

| 受影响对象 | 现状 | 处理 |
|---|---|---|
| ECharts tooltip | 项目规定 `appendToBody: true`（防遮挡） | 全屏态改为 `appendToBody: false`，或 ECharts 5.5+ 的 `tooltip.appendTo` 指向全屏容器；退出全屏改回 `true` |
| `el-select`（趋势天数） | 默认 `teleported=true` 挂 body | 全屏态 `:teleported="false"`，并给父级加 `position: relative` |
| `el-tooltip`（榜单下载按钮等） | 默认挂 body | 同上，`teleported=false`，或全屏态改为 `el-tooltip` 禁用后仅靠图标语义 |
| `ElMessage`（错误提示） | 全局挂 body | 全屏态下错误提示**不可见**；建议全屏态失败时改为「图表内角标 + 控制台」，或在触发提示时先 `exitFullscreen()` 再提示 |

> 若不做上述处理，全屏后趋势图 tooltip、天数下拉框会直接"点了没反应"，属于致命体验问题。
> 这也是「CSS 伪全屏」方案的优势面：伪全屏是普通文档流定位，body 弹层不受影响（只需控制 z-index 低于弹层 2000+ 即可）。

### 5.7 全屏与懒加载的冲突

`DashboardView` 用 `IntersectionObserver`（`rootMargin: 200px`）懒加载「分版块对比」与「热门榜」。全屏后视口变高，理论上可见内容更多，但：

- 若内容区高度超过一屏，热门榜仍在视口外 → 全屏后**大片空白**；
- 建议：进入全屏时主动 `loadBoards()` / `loadFidTrend()`（已加载则跳过，两个 loader 都有幂等判断口径），保证大屏一次性铺满。这是小改，但缺了会明显掉价。

## 6. 推荐方案对比

### 6.1 侧边栏方案

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. EP collapse + el-drawer（推荐）** | 桌面 `el-menu` 折叠为图标条；移动 `el-drawer` 抽屉 | 零新依赖、EP 原生能力、交互符合用户预期、改造面小 | 折叠态需自补 tooltip | ✅ 采用 |
| B. 自研 fixed + transform 抽屉 | 手写遮罩、动画、焦点管理 | 完全可控、动画可定制 | 与 EP 风格不一致、无障碍/焦点/滚动锁定都要自己写，代码量翻倍 | ❌ |
| C. 移动端改顶部 Tab / 底部 TabBar | 隐藏侧栏，改横向导航 | 移动端最省空间 | 与现有 5 路由 + EP 生态割裂，桌面/移动两套 UI 心智负担大 | ❌ |

### 6.2 全屏方案

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **1. Fullscreen API 作用于右侧内容区（推荐）** | `.body` 容器 `requestFullscreen` | 真全屏、隐藏浏览器 UI；Header 时钟/自动刷新保留；侧栏自动消失 | 需处理 body 弹层挂载（5.6）；iOS Safari 不支持 → 需降级 | ✅ 主方案 |
| 2. Fullscreen API 作用于整个 layout + 自动折叠侧栏 | 整页全屏 | 侧栏仍可点击切换页面（大屏可轮播） | 侧栏/Header 占屏，观感接近 F11，按钮价值打折；仍需处理弹层 | ❌ |
| 3. CSS 伪全屏（fixed 覆盖） | `position: fixed; inset: 0` | 全浏览器一致、弹层无问题、实现最简单 | 非真全屏（地址栏/任务栏仍在）、多屏不友好 | ✅ 作为方案 1 的**降级** |
| 4. 独立大屏路由 + 1920 等比 scale | 新增 `/screen` 页 + `transform: scale` | 还原度最高、最像"大屏" | 违反本项目「路由固定 5 条」约束；新增整页重复实现；scale 导致字体模糊、点击热区偏移 | ❌ |

### 6.3 大屏适配风格

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **a. 自适应栅格 + vh 高度（推荐）** | 沿用现有 grid 断点，全屏态用 CSS 变量抬高图表高度与字号 | 清晰不模糊、点击热区正确、与现有 grid 结构零冲突、改造量小 | 非 16:9 屏需要容忍轻微比例差异 | ✅ 采用 |
| b. 等比缩放 scale（autofit.js / v-scale-screen 思路） | 设计稿 1920×1080 整体缩放 | 一行接入、还原度高 | 字体模糊、热区偏移、非 16:9 留黑边；需引第三方脚本（违反「不引新依赖」） | ❌ |

**综合推荐：A（折叠/抽屉）+ 1（真全屏，3 降级）+ a（自适应密度）**。

## 7. 风险评估与规避

| # | 风险 | 影响 | 概率 | 规避措施 |
|---|---|---|---|---|
| 1 | **ECharts 不随折叠/抽屉/全屏 resize** | 图表裁切、错位、留白 | 高（不处理必现） | `ResizeObserver` + `nextTick` 主动 resize（5.3） |
| 2 | **全屏后弹层不可见**（tooltip / select / Message） | tooltip 与下拉"点了没反应" | 高（不处理必现） | 全屏态切换 `appendToBody` / `teleported`，Message 降级（5.6） |
| 3 | **Esc / F11 退出导致按钮状态不同步** | 按钮失灵、样式残留 | 中 | 监听 `fullscreenchange` 单向同步 store；全屏态也提供页面内退出按钮 |
| 4 | **iOS Safari / iframe 不支持元素全屏** | 按钮无反应 | 中 | 特性检测 + CSS 伪全屏降级（5.4）；iframe 场景需 `allowfullscreen`（本项目无 iframe，暂不涉及） |
| 5 | **全屏 + 5s 轮询的性能压力** | 4 个 ECharts 实例放大后重绘成本上升，大屏卡顿 | 中 | 全屏态关闭入场动画（`animation: false`）；已有 `visibilitychange` 暂停机制继续生效；必要时全屏态轮询放宽至 10s（需你确认，默认**不改** 5s） |
| 6 | **懒加载区块在全屏后空白** | 大屏下半屏空 | 中 | 进入全屏主动触发已注册的懒加载（5.7） |
| 7 | **折叠态菜单可读性** | 纯图标看不懂 | 低 | 折叠态 `el-tooltip` 右侧提示 |

### 10.3 与原方案的 4 处差异（实施中修正）

1. **折叠态 tooltip 无需自补**：Element Plus 的 `el-menu-item` 在 `collapse` 态会自动用内置 popper 展示 `#title` 内容，因此未额外加 `el-tooltip`，避免双重气泡。
2. **全屏切换必须重建 ECharts 实例**（原方案仅写「清空数据指纹强制重绘」）：实测 ECharts 的 Tooltip 挂载容器（`appendTo` / `appendToBody`）在实例初始化时即确定，后续 `setOption` 修改不生效 —— 全屏后 tooltip 仍挂在 body（实测「全屏内 0 个、全屏外 1 个」）。改为 `rebuildCharts()`：dispose 4 个实例 → 复位联动标记 `trendTipSynced` / `fidTipSynced` → 清空 P1-8 数据指纹 → 重建并重启轮播。修复后实测「全屏内 1 个、全屏外 0 个」。
3. **`.trend-half .trend-chart-wrap` 需一并变量化**：该规则优先级高于 `.trend-chart-wrap`，把趋势图高度钉死在 300px，导致 `--chart-h` 在全屏态不生效。已改为 `height: var(--chart-h, 300px)`。
4. **顺带修复 `<Timer />` 未注册**：`AppLayout` 模板使用 `<Timer />` 但 `main.ts` 未注册，运行时会输出 "Failed to resolve component" 警告且时钟图标不显示。已在 `main.ts` 补注册。

### 10.5 已知限制

- **全屏态弹提示会自动退出全屏**：真全屏下挂在 body 的 `ElMessage` 不可见，因此 `notifyError` / `notifySuccess` 会先退出全屏再提示（加载失败、创建下载任务等场景）。
- **iOS Safari 降级**：不支持元素级 `requestFullscreen`，自动降级为 CSS 满屏（地址栏/任务栏仍可见），功能可用但非真全屏。
- **大屏按钮仅数据总览提供**：其余 4 个页面全屏后分页与弹层层级复杂，暂不提供。
- **全屏态不改图表内字号**：图表 option 中的字号写死且参与 P1-8 数据指纹，改动会牵连重绘逻辑；当前仅放大 KPI 数值（26 → 32px）与图表高度，收益/成本比更高。
