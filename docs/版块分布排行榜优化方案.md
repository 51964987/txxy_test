# 版块分布 · 排行榜优化方案

> 本文档针对数据总览大屏中的「版块分布 · 排行榜」进行深度分析，参考同类项目（DataV、Grafana、Ant Design Charts、GitHub Trending、掘金/知乎热榜等）的最佳实践，提出多维度优化方案。
>
> **状态：待用户确认后实施**（当前仅输出方案，未变更任何代码）

---

## 一、现状分析

### 1.1 当前实现概览

| 维度 | 当前实现 |
|------|----------|
| 布局 | 卡片头部标题「版块分布 · 排行榜」+ 8 行可视区列表 |
| 行结构 | grid 四列：`名次徽章 | 版块名(fid) | 今日新增/最新 | 总量条数(占比)` |
| 名次徽章 | 前 3 名渐变（金/银/铜），其余浅灰 `rank-plain` |
| 行高 | 固定 `40px`，8 行可视区高度 `320px`，与右侧环形图等高 |
| 轮播 | 数据 > 8 行时，每 `2000ms` 平滑上滚一行，末尾补位 `(N-1)` 行实现无缝循环 |
| 交互 | 悬停暂停轮播、离开恢复；点击行跳转 `/posts?fid=xxx`；tooltip 显示最近抓取/今日/昨日 |
| 数据源 | `fidDist`：`name`、`fid`、`count`（总量）、`today_count`、`yesterday_count`、`latest_date` |

### 1.2 待提升空间

| 维度 | 现状 | 可提升方向 |
|------|------|-----------|
| **视觉层次** | 纯文字行 + 名次徽章，缺少横向进度条 | 增加占比进度条、渐变强调前 3 名、徽章尺寸优化 |
| **信息丰富度** | 仅展示总量 + 今日/昨日 | 增量趋势箭头、环比、Sparkline 迷你趋势 |
| **交互深度** | 点击跳转 + 悬停暂停 | 行悬停高亮 + 与右侧环形图联动、点击排序切换 |
| **动效精致度** | 单条上滚轮播 | 渐变显隐、当前行高亮跟随、悬浮放大 |
| **数据维度** | 仅按总量排序 | 支持按今日/昨日/总量切换排序维度 |
| **响应式** | 窄屏隐藏「今日新增」列 | 更多断点适配、横向滚动处理 |

## 二、优化方案

### 方案 A：视觉层次增强（推荐优先实施）

#### A1. 占比横向进度条

**现状**：总量仅以文字 `xxx 条 (xx.x%)` 展示，占比强弱不直观。

**优化建议**：为每行增加一条底部细进度条，宽度 = 该版块 count 占总量百分比，颜色随名次渐变（前 3 名用对应徽章色，其余用版块主色 `#2f6fed`）。

```css
.bar-row {
  /* 现有 grid 不变，进度条作为 ::after 装饰层 */
  position: relative;
}
.bar-row::after {
  content: '';
  position: absolute;
  left: 44px; /* 避开名次徽章 */
  right: 10px;
  bottom: 4px;
  height: 3px;
  border-radius: 2px;
  background: var(--bar-progress, rgba(47, 111, 237, 0.18));
  transform-origin: left center;
  transform: scaleX(0);
  transition: transform 0.6s cubic-bezier(0.22, 1, 0.36, 1);
}
.bar-row::before {
  content: '';
  position: absolute;
  left: 44px;
  bottom: 4px;
  height: 3px;
  width: var(--bar-width, 0%);
  border-radius: 2px;
  background: linear-gradient(90deg, #2f6fed, #6366f1);
}
```

> 说明：`--bar-width` 由 JS 按 `count / fidDistTotal * 100%` 动态设置；利用 `::before` 做静态进度、`::after` 做入场动画，避免依赖额外 DOM。

**效果**：
- 一眼看出各版块体量差异
- 与右侧环形图占比形成呼应
- 入场时进度条从 0 生长，增强数据大屏仪式感

**同类参考**：GitHub Trending、掘金热榜、Ant Design 进度条。

**优先级**：⭐⭐⭐ 高　**风险评估**：低，纯装饰 + 少量内联变量。

---

#### A2. 前三名高亮强化

**现状**：前 3 名仅徽章颜色不同，整行视觉权重差异不大。

**优化建议**：
1. 前 3 名行背景淡渐变 + 左侧粗色条（金色 `#fbbf24`、银色 `#cbd5e1`、铜色 `#e8a17c`）。
2. 冠军行（rank 1）增加微发光阴影 + 「TOP」角标。

```css
.bar-row.rank-1 {
  background: linear-gradient(90deg, rgba(251, 191, 36, 0.10), rgba(251, 191, 36, 0.02));
  box-shadow: inset 3px 0 0 #fbbf24;
}
.bar-row.rank-2 {
  background: linear-gradient(90deg, rgba(203, 213, 225, 0.12), rgba(203, 213, 225, 0.02));
  box-shadow: inset 3px 0 0 #cbd5e1;
}
.bar-row.rank-3 {
  background: linear-gradient(90deg, rgba(232, 161, 124, 0.12), rgba(232, 161, 124, 0.02));
  box-shadow: inset 3px 0 0 #e8a17c;
}
```

**效果**：前三名在滚动轮播中快速被眼球捕捉，符合热榜的"头部聚焦"惯例。

**同类参考**：微博/知乎热榜前三名的头部强调。

**优先级**：⭐⭐⭐ 高　**风险评估**：低，纯 CSS class 控制。

---

#### A3. 名次徽章优化（动态宽度 + 上升/下降角标）

**现状**：徽章固定 22px 方形，无趋势信息。

**优化建议**：
1. 前 3 名使用圆形徽章（radius 50%），尺寸略大（24px），更醒目。
2. 4 名以后使用小号圆角标签。
3. 每行名次旁增加「较昨日上升/下降/持平」小箭头（需要后端提供排序变化数据，可选）。

```css
.bar-rank.rank-gold,
.bar-rank.rank-silver,
.bar-rank.rank-bronze {
  width: 24px;
  height: 24px;
  border-radius: 50%;
}
```

**优先级**：⭐⭐ 中　**风险评估**：趋势箭头需后端支持 `prev_rank`，否则仅做徽章形状升级。

---

### 方案 B：信息密度提升

#### B1. 今日/昨日增量趋势箭头

**现状**：`today_count`/`yesterday_count` 并列展示，未表达增减。

**优化建议**：计算 `today_count - yesterday_count`，正负分别用绿色 `↑` / 红色 `↓`，并加 `±n` 数值。

```html
<span class="bar-delta" :class="deltaCls">
  <el-icon v-if="delta > 0"><CaretTop /></el-icon>
  <el-icon v-else-if="delta < 0"><CaretBottom /></el-icon>
  <el-icon v-else><Minus /></el-icon>
  <span>{{ Math.abs(delta).toLocaleString() }}</span>
</span>
```

```js
const delta = (row.item.today_count ?? 0) - (row.item.yesterday_count ?? 0)
const deltaCls = delta > 0 ? 'delta-up' : delta < 0 ? 'delta-down' : 'delta-flat'
```

**效果**：一眼看出哪些版块在涨/跌，信息价值远超纯数字。

**同类参考**：掘金/InfoQ 热榜的增量角标。

**优先级**：⭐⭐⭐ 高　**风险评估**：低，纯前端计算，字段已具备。

---

#### B2. 行内迷你趋势（Sparkline，可选）

**现状**：无历史走势，无法判断版块活跃趋势。

**优化建议**：在行内嵌入一个轻量 SVG 迷你折线（复用 `latest_date` 前若干天数据，需后端提供按 fid 的日增量序列）。若后端暂不提供，可先跳过。

```html
<svg width="56" height="16" class="bar-spark">
  <polyline :points="sparkPoints" fill="none" stroke="#2f6fed" stroke-width="1.5" />
</svg>
```

**优先级**：⭐⭐ 中　**风险评估**：中，**需后端新增接口**（如 `/api/stats/fid-trend?fid=xx&days=7`），且数据量随行数增长，建议仅在悬停时按需加载。

---

#### B3. 底部汇总条

**现状**：列表底部无汇总，信息闭环不完整。

**优化建议**：在可视区最后固定一行汇总：`版块总数 N · 累计帖子 M 条`，与 `fidDistTotal` 联动。

```html
<div class="bar-total-bar">
  <span>共 {{ fidDist.length }} 个版块</span>
  <span>累计 {{ fidDistTotal.toLocaleString() }} 条</span>
</div>
```

**优先级**：⭐⭐ 中　**风险评估**：低。需注意汇总行不参与轮播，固定在底部。

---

### 方案 C：交互增强

#### C1. 与右侧环形图联动高亮

**现状**：排行榜与环形图独立展示，无联动。

**优化建议**：悬停排行榜某行时，环形图同步 `highlight` 对应扇区（已实现的 `pieChart.dispatchAction` 可复用）；点击行时环形图高亮并暂停轮播。

```js
function highlightFid(idx) {
  pieChart.value?.dispatchAction({ type: 'downplay', seriesIndex: 0 })
  pieChart.value?.dispatchAction({ type: 'highlight', seriesIndex: 0, dataIndex: idx })
}
```

**效果**：两块图表形成"左右互文"，信息一致性大幅提升，数据大屏交互感更强。

**同类参考**：DataV 大屏的"榜单 ↔ 地图/图表联动"。

**优先级**：⭐⭐⭐ 高　**风险评估**：低，复用现有 ECharts dispatchAction，无新依赖。

---

#### C2. 排序维度切换

**现状**：固定按 `count`（总量）排序。

**优化建议**：卡片头部增加 Tab：`总量 | 今日新增 | 昨日新增`，切换排序字段并重置轮播。当前 `fidDist` 已含 `today_count`/`yesterday_count`，前端即可完成，无需后端改造。

```html
<el-radio-group v-model="sortField" size="small">
  <el-radio-button value="count">总量</el-radio-button>
  <el-radio-button value="today">今日</el-radio-button>
  <el-radio-button value="yesterday">昨日</el-radio-button>
</el-radio-group>
```

```js
const sortedFid = computed(() =>
  [...fidDist.value].sort((a, b) => (b[sortField.value] ?? 0) - (a[sortField.value] ?? 0))
)
```

**效果**：从"单一静态榜单"升级为"可多视角洞察"，实用性显著提升。

**同类参考**：GitHub Trending（今日/本周/本月切换）、V2EX 热榜。

**优先级**：⭐⭐⭐ 高　**风险评估**：低，数据字段已具备，需注意排序维度切换后名次徽章与轮播的同步。

---

#### C3. 行悬停 Tooltip 增强

**现状**：行 tooltip 以原生 `title` 展示（最近抓取/今日/昨日），样式简陋。

**优化建议**：改为自定义浮层，展示：版块名、累计总量、占比、今日/昨日/近7日、最近抓取时间，并以 mini 进度条直观呈现占比。

**优先级**：⭐⭐ 中　**风险评估**：低，纯前端。

---

### 方案 D：动效精致度

#### D1. 轮播当前行高亮跟随

**现状**：轮播滚动时无"当前浏览项"指示。

**优化建议**：随 `barIndex` 更新，为当前行添加淡蓝色高亮背景，滚动到下一行时平滑迁移。

```css
.bar-row.is-active {
  background: #f0f4ff;
}
```

**优先级**：⭐⭐ 中　**风险评估**：低。需在 `startBarScroll` 的 `setInterval` 内同步 `activeIndex`。

---

#### D2. 入场渐显 + 名次徽章弹跳

**现状**：整列直接渲染，无入场动效。

**优化建议**：
- 首屏：每行延迟 `i * 60ms` 从左侧淡入 + 轻微上移。
- 名次徽章：前三名入场时 `scale 1→1.15→1` 弹性动画。

```css
@keyframes rowIn {
  from { opacity: 0; transform: translateX(-12px); }
  to   { opacity: 1; transform: translateX(0); }
}
.bar-row { animation: rowIn 0.4s ease both; }
.bar-row:nth-child(1) { animation-delay: 0.05s; }
.bar-row:nth-child(2) { animation-delay: 0.11s; }
/* ...依次递增... */
```

**优先级**：⭐⭐ 中　**风险评估**：低。注意轮播补位行也应获得动画，避免入场闪烁。

---

### 方案 E：响应式与无障碍

#### E1. 更多断点适配

**现状**：仅 `max-width: 1100px` 时隐藏「今日新增」列。

**优化建议**：
- `≤1100px`：隐藏 `.bar-sub`，grid 收窄为 3 列（已有）。
- `≤768px`：隐藏 `.bar-metric` 的占比，仅保留数量；行高可降至 36px，可视行数减至 6。
- 排行列表宽度不足时，允许 `.bar-name` 省略号截断（已具备 `overflow: hidden; text-overflow: ellipsis`）。

**优先级**：⭐⭐ 中　**风险评估**：低。注意 `BAR_ROW_HEIGHT`/`BAR_VISIBLE_ROWS` JS 常量需与 CSS 同步。

#### E2. 减少运动偏好

**优化建议**：通过 `@media (prefers-reduced-motion: reduce)` 关闭轮播/入场动画，照顾对动画敏感用户。

```css
@media (prefers-reduced-motion: reduce) {
  .bar-row { animation: none !important; }
  .bar-list { scroll-behavior: auto; }
}
```

**优先级**：⭐ 低　**风险评估**：低。

## 四、推荐实施路线

### 第一批（高性价比，纯前端，建议优先）

> 目标：不改后端、不改数据流，仅通过 CSS + 现有字段提升视觉与信息表达。

| 实施项 | 预计改动量 | 效果提升 |
|--------|------------|----------|
| **A1 占比进度条** | ~20 行 CSS + 少量内联变量 | 体量对比一目了然，数据大屏质感 |
| **A2 前三名高亮** | ~10 行 CSS class | 头部聚焦，热榜惯例 |
| **B1 增量趋势箭头** | ~15 行模板/脚本 | 涨跌直观，信息价值提升 |
| **C1 与环形图联动** | ~10 行 JS（复用 dispatchAction） | 两块图表互文，交互连贯 |
| **C2 排序维度切换** | ~20 行 computed + 头部 Tab | 多视角洞察，实用性提升 |

### 第二批（锦上添花）

| 实施项 | 说明 |
|--------|------|
| **D1 轮播高亮跟随** | 当前行指示，轮播更清晰 |
| **D2 入场渐显动画** | 首屏仪式感 |
| **B3 底部汇总条** | 信息闭环 |
| **A3 徽章优化** | 前三名圆形 + 趋势角标（需后端 prev_rank） |
| **C3 行悬停 Tooltip** | 原生 title 升级为自定义浮层 |

### 第三批（需后端或按需）

| 实施项 | 前置条件 | 说明 |
|--------|----------|------|
| **B2 行内迷你趋势** | 后端提供按 fid 的日增量序列 | 悬停按需加载 |
| **E1 多断点适配** | 确认移动端使用需求 | 同步 JS 常量 |
| **E2 减少运动偏好** | 无障碍规范要求 | 纯 CSS |

## 五、技术风险与约束

| 风险 | 说明 | 缓解措施 |
|------|------|----------|
| 进度条与轮播冲突 | `::before/::after` 宽度基于百分比，轮播补位行复用数据 | 复用 `--bar-width`，补位行同步设置 |
| 排序切换重排 | 切换维度后名次变化，徽章/进度条需重新计算 | 基于 `sortedFid` 派生 computed，统一数据源 |
| 环形图联动状态 | 联动高亮与环形图自动轮播冲突 | 联动时暂停 `pieTimer`，移出后恢复 |
| 迷你趋势性能 | 每行一个 SVG，多行渲染 | 悬停按需加载 + 缓存；仅少量行启用 |
| 断点高度不同步 | CSS 行高与 JS 常量不一致会导致错位 | 抽取公共变量，或 JS 读取 `getComputedStyle` 计算 |
| 动画与轮播叠加 | 入场动画与 `scrollTop` 上滚可能闪烁 | 入场动画仅在首屏一次性执行，轮播期不加动画 |
