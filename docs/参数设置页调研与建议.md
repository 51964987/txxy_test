## 二、业界做法

| 产品 | 设置形态 | 生效与持久化 |
|---|---|---|
| **aria2 / AriaNg / Motrix** | 独立「基本设置 / 高级设置」页：最大同时下载数、单任务连接数、每服务器连接数、分段数、超时、重试、限速 | 运行时经 RPC `aria2.changeGlobalOption` 立即生效，写回配置文件持久化 |
| **qBittorrent / Transmission WebUI** | 设置页：队列最大活动下载数、全局/单任务限速、做种上限 | 运行时生效，写回配置文件 |
| **IDM / FDM** | 选项对话框：连接数（默认 8）、超时、重试 | 立即生效 |
| **通用后台管理系统** | 独立「系统设置 / 参数设置」页，分组 + 每项标注生效范围（立即 / 下次 / 需重启） | 落库或落配置文件 |

**结论**：
1. 并发/重试/限速这类**运行时行为参数**在业界**默认就是 UI 可调 + 运行时生效**；
2. 但**没有产品允许在 UI 改数据目录、监听端口、域名**——那属于部署配置（env / 配置文件）；
3. 通行细节：**每项标注生效范围**、提供**恢复默认**、危险项二次确认。

## 四、方案设计

### 4.1 配置层级（避免「两处默认值」）

```
页内设置文件 outputs/web_settings.json  >  环境变量  >  代码默认值
```

- 仅**白名单内**的键接受文件覆盖，其余一律回落到环境变量/默认值——避免把端口、路径、域名这类部署配置意外挪进 UI；
- 沿用「唯一默认值定义处」原则：白名单键的默认值仍在 `config.py` 定义，设置文件只存**用户覆盖值**（缺失即回落），不复制第二份默认值；
- 落盘复用既有 `web/atomicfile.py`（原子写 + 可选 `.bak`），损坏时按「文件不可用即静默回落」处理（与现有 `ResourcesView` 的 sessionStorage 容错风格一致）。

### 4.2 配置层改造（关键：从常量到读取函数）

现状 `config.DOWNLOAD_CONCURRENCY` 等是**模块级常量**，被下游直接引用（引用点：`download_tasks._execute`、`manager.start`、`api.py` 提交上限、`resources.list_trash`、`resources.scan`、`/api/config`）。改造为「常量保留为默认值 + 提供读取函数/可变运行时值」：

- 新增 `web/settings.py`：加载/保存设置文件、提供 `get(key)` / `set(key, value)`、白名单校验与范围钳制；
- `config.py` 保留默认值定义，导出读取入口（下游改为读函数，改动点仅个位数行）；
- 不在 `settings.py` 里再写一份默认值——与 CODEBUDDY「默认值只在配置源定义一次」一致。

### 4.3 接口与前端

- `GET /api/config`（已有）：扩展为返回**白名单参数的当前生效值 + 来源（default/env/file）**，供设置页回显；
- 新增 `PUT /api/config`（或 `POST /api/settings`）：保存并返回保存后的生效值；非法值 400（带字段说明）；
- 前端新增设置页（**需确认第 7 条路由 `/settings`**，当前约定为 6 条路由）：按「下载 / 资源 / 界面 / 高级」分组，每项标注生效范围，提供「恢复默认」；
- 保存后：**即时型**参数由前端直接应用（如自动刷新）；**准实时型**由下一次调用自然生效；UI 明示，不做隐式重启。

### 4.4 实时 / 准实时机制（回答「任务能否实时接受变化」）

| 类型 | 参数 | 机制 | 是否影响正在跑的任务 |
|---|---|---|---|
| **准实时（下一任务生效）** | 单任务内并发、下载间隔、重试 | `_execute` 每次执行读一次 | ❌ 不影响（业界同：aria2 变更选项对已开始任务不回溯） |
| **准实时（立即/下次调用）** | 提交上限、历史保留、回收站天数、扫描 TTL | 各调用点每次读 | — |
| **准实时需小改造** | 任务间并发（调小）、限流窗口 | 调小：向队列推 `None` 哨兵让多余 worker 退出（机制已存在，未对外暴露）；限流需按新窗口重建计数器 | 不影响在跑任务 |
| **即时（前端）** | 自动刷新开关 | 保存后前端直接应用，不必等下次拉取 | — |
| **需重启（不开放）** | 端口、路径、域名、监听地址 | — | — |

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 并发/重试调高触发源站限流、封 IP | 白名单范围钳制（并发 ≤8、间隔 ≥0）；UI 给出默认值与「过高有封禁风险」说明 |
| 调高并发放大「同目录并发写」 | 与既有判重（同 URL 去重）配合；必要时提示「同目录多链接不建议高并发」 |
| 把端口/路径/域名挪进 UI 导致服务起不来 | 严格白名单，三者不开放（业界同：属部署配置） |
| 设置文件损坏/半写 | `atomicfile` 原子写 + 解析失败回落默认值并告警 |
| Web 无鉴权（单人自用前提） | 设置页等同本机配置，风险可接受；若未来开放多人需先补鉴权再开放写配置 |
| 任务已启动后改参数造成行为不一致 | 明确「下一任务生效」，UI 标注；与 aria2 行为一致 |

## 七、建议分期

- **P0（建议先做）**：白名单配置层 + 设置页，开放「单任务内并发 / 提交上限 / 历史保留 / 回收站保留天数 / 扫描 TTL / 自动刷新开关」——全部为准实时，零 worker 生命周期改动，风险最低。
- **P1**：任务间并发（含 worker 收缩）、下载间隔与重试次数（触达 `download_files.py`，需与 CLI 默认值同源）。

- **不做**：端口 / 路径 / 域名 / DB 相关 / UA。

## 九、实施记录（2026-09-08，P0 + P1 落地；上述 4 项均确认「是」）

**后端**

- 新增 `web/settings.py`：白名单（10 个参数）+ 范围钳制 + 原子落盘（`outputs/web_settings.json`）+ 来源标注（`file` / `default`）；默认值**不在此重复定义**，各参数默认值仍归其归属模块（`config.py` / `download_files.py` / `resources._CACHE_TTL`），本模块只存覆盖值；提供 `get/get_int/get_float/get_bool`、`snapshot()`、`update()`、`reset()`、`apply_runtime()`。

- `download_files.py`（项目根）：新增 `configure(interval, max_retries, retry_delay)` 改模块级运行态；**默认值仍定义在该模块一份**，CLI 不受影响，Web 侧保存设置时同步。
- `web/resources.py`：回收站保留天数、扫描缓存 TTL 改读设置（每次调用读 → 立即生效）。
- `web/app.py`：`startup` 时 `settings.apply_runtime()`，保证重启后已保存设置继续生效（失败仅告警、回落默认值，不阻断启动）。

**前端**

- 新增第 7 条路由 `/settings`（`SettingsView.vue`）与侧边栏入口；按「下载 / 资源与回收站 / 界面」分组，每项显示说明、默认值、**生效范围**、是否「已自定义」；提供单项与全部**恢复默认**、保存后提示；移动端行内堆叠、控件不溢出。

**实测**

- 接口：`GET /api/config` 返回 10 个参数；保存 `trash_keep_days=3` → `/api/resources/trash` 立即返回 3；`resources_scan_ttl=2` → 子目录新增文件 3 秒后即被扫到（默认 10s 时不会）；`download_max_batch=10` → 提交 11 条返回 400；设置文件落盘；`reset` 后回落到默认 7 且 `source=default`（`SETTINGS-API-PASS`）。
- 并发：`download_task_concurrency=2` → 两个任务**同时 running**（worker 补足生效），随后恢复默认（`CONCURRENCY-RESIZE-PASS`；测试任务已删除）。

- 自检：`py_compile`（6 个后端文件）/ `vue-tsc --noEmit` / `read_lints` 全 0；`npm run build` 成功，dist 已更新。

## 十、后续演进（2026-09-16）

### 10.1 新增「定时抓取」组 + `times` 参数类型

- 白名单从 10 项扩到 14 项（`scrape_schedule_enabled` / `_times` / `_restart` / `_use_proxy`），置于「下载」之前；
- 新增 **`times` 类型**（值为 `string[]`，形如 `["08:00","20:00"]`）：钳制统一走 `config.normalize_times()`（丢弃非法项、去重、升序、限量 6 条），前端用「时刻列表（逐行时刻选择器 + 增删）」渲染，**不用 cron 表达式输入框**（对非技术使用者易错且无预览；Windows 任务计划程序 / Vercel Cron / Grafana 都用枚举式）；
- 组内带**只读状态区**（当前状态 / 下次执行 / 今日已处理 / 上次结果 / 调度线程心跳 + 「立即运行一次」），状态 5 秒轮询、页面不可见时暂停；
- 参数默认值与调度实现归 `web/config.py` 与 `web/scheduler.py`，本页仍只存覆盖值（沿用 4.1 的配置层级）；完整设计与实测见《定时抓取调度调研与建议.md》。

### 10.2 宽控件行改为堆叠布局（修「演示轮播」卡片错位）

**问题（用户上报）**：「演示轮播」卡片看起来错位。**不靠肉眼判断，先用 bounding box 量**：该组第二行（`carousel_sections`，`array` 类型）的控件固有宽度为 **1002px**（被其中的「默认：总览首屏 → … → 热门榜」长句撑开），而 `.sr-main` 是 `flex: 1; min-width: 0`，于是标签列被压到 **132px**、描述文字挤成竖条——与同组第一行（控件 235px、左右分栏）形成明显不对称。

**修复**：把「控件固有宽度很宽」的类型标记为**宽控件行**（`WIDE_TYPES = ['array', 'times']`），这类行改为**标签在上、控件在下**（`.setting-row.row-wide { flex-direction: column }`，控件 `width: 100%`、「恢复默认」换行后仍贴右）；紧凑控件（开关 / 数字 / 下拉 / 文本）保持左右分栏。对照业界：Element Plus / Ant Design 的表单对复杂控件（多选组、列表编辑器）也一律独占一行，只有紧凑控件才与标签同排。

**实测**（真实页面量测）：标签列宽 132 → **1150**；控件移到标签下方且占满整行（array 宽 1150）；同组紧凑行仍为左右分栏（main 899 / ctrl 235）;「抓取时刻」同属宽控件行，同样堆叠；移动端 390px 下控件宽 312 ≤ 视口、无横向溢出。

### 10.3 链接黑名单：搜索 + 分页 + 计数（回答「数据太多怎么显示」）

**问题**：黑名单条目变多后，设置页被拉成一条望不到头的长列表（实测 17 条时该卡片已高 776px）。

**业界做法对比**（管理型列表）：

| 方案 | 适用 | 本项目取舍 |
|---|---|---|
| **分页 + 搜索 + 计数** | 条目需被逐条查看/删除的管理列表（Element Plus 后台表格、Ant Design Table、GitHub「blocked users」） | **采用**：确定性最强——"共多少条、在第几页、能搜到"，且与下载中心/资源管理页的既有分页口径一致 |
| 无限滚动 / 加载更多 | 信息流（社交、日志 tail） | 不采用：管理场景需要总数与定位，滚到哪儿全靠猜 |
| 纯滚动容器（max-height + overflow） | 抽屉/弹窗里的短列表 | 不采用：只是把长列表换个地方滚，仍无法快速定位 |
| 虚拟滚动 | 上千~上万条 | 当前不需要（几十条），且实现与依赖成本高 |

**实现**：前端切片分页（**每页 5 条**——经用户确认，与运行记录页「每页 5 条」同一口径；`el-pagination` 小号 + background；仅一页时不出分页器）、搜索框（按 **value / 备注 / 类型名** 匹配，备注也参与——用户常按"为什么拉黑"的备注找）、计数（`共 N 条`，筛选时追加 `筛选出 M 条`）；筛选变化回到第 1 页、条目减少或筛选变窄时页码收敛到最后一页（防止停在空页上）。移动端搜索框独占一行、分页器居中。

**升级触发条件（交底）**：当前是**前端切片**，前提是接口已全量返回、量级在"几十条"。一旦黑名单条目数进入**数百条以上**（接口响应体与首屏渲染开始有感），应改为**服务端分页**（`GET /api/blacklist?page=&size=&q=`），届时前端只需换成把 page/size/q 传上去——分页控件与计数展示无需改动。

**实测**（真实数据 17 条，全程只读、未增删任何条目）：每页 5 条 → 首页 5 条、末页 2 条（共 4 页）、计数「共 17 条」、分页器仅在多页时出现、搜索真实片段命中 1 条并显示「共 17 条，筛选出 1 条」、筛选后不足一页时页码自动收敛且分页器隐藏、清空搜索恢复首页 5 条；移动端搜索框占满整行、分页器可见。15 项浏览器断言全通过（每页条数变更后按 5 条复验）。

## 十一、`TXXY_PUBLIC_DOMAIN` 要不要放进参数设置页（2026-09-17 复核：**不放**）

**结论**：不放进设置页（保持 `txxy_env.py` 唯一配置源，靠 `.env` / 环境变量 + 重启）；设置页最多只做**只读回显**。

**判定标准（两条，业界通用）**：

1. **是不是自举 / 自指参数**——「应用靠它才能被正确访问」。这类参数一旦页内改错，可能导致**再也进不去改回来**（lockout），故业界一律放配置文件/环境变量。
2. **是不是跨进程 / 跨环境共享**——页内设置通常只被**一个进程**加载；若同一参数还被 CLI 子进程、定时任务、容器 cron 读取，页内改就会造出「页面显示 A、实际跑的是 B」的分裂。

**业界对照**：

| 产品 | 该类参数 | 放置位置与生效方式 | 页内可改？ |
|---|---|---|---|
| WordPress | `WP_HOME` / `WP_SITEURL`（站点地址） | `wp-config.php`；官方明确「后台 siteurl 填错时用常量覆盖以恢复」 | 后台表单可改但**官方建议用常量锁定**（改错会丢后台入口，属经典 lockout） |
| GitLab | `external_url` | `/etc/gitlab/gitlab.rb` + `gitlab-ctl reconfigure` | 否 |
| Grafana | `root_url` / `server.domain` | `grafana.ini` / `GF_SERVER_ROOT_URL` 环境变量 | 否（About / 配置页只读展示） |
| Nextcloud | `trusted_domains` / `overwrite.cli.url` | `config/config.php` | 否 |
| MediaWiki | `$wgServer` | `LocalSettings.php` | 否 |
| Jenkins | Jenkins URL | 页内可改 | **可改**，但官方专门写「改错后如何恢复」（改名/改地址后 UI 打不开，只能改 XML 或用启动参数）——反面教材 |
| Sonarr / Radarr | Host / URL Base | 页内可改 | 可改（因为不是自举参数），但官方同样警告「改 URL Base 会立刻断开当前访问」 |

⇒ 归纳：**自举 / 自指 / 跨进程共享的地址参数一律配置文件 + 重启，页内最多只读回显**；只有「运行时可变的业务数据」（数据源地址、通知地址、外部 API 密钥…）才适合页内编辑。

**本项目的三点判定**：

1. **不是自举参数**：看板自己的访问地址是 `TXXY_WEB_HOST` / `TXXY_WEB_PORT`（在 `web/config.py`），`TXXY_PUBLIC_DOMAIN` 是**被采集/被打开的目标站点域名**，改错不会导致看板进不去 → 不存在 lockout，所以不是"绝对禁止"；
2. **但它跨进程共享**：`txxy_env.py` 同时被抓取 CLI（`scraper.py` / `run_batch.py`）、Web 进程、Docker `cron` 容器读取；而 `web/settings.py` 的覆盖值只落在 `outputs/web_settings.json`、且**只有 Web 进程加载**（抓取子进程根本不 import 它）。页内改 ⇒ 只影响展示 / 导出 / 中继降级，抓取仍走环境变量里的值 → 直接违反「同一概念只允许一处配置」（CODEBUDDY 通用约束第 1 条）；
3. **部署环境另有权威**：Docker 由 compose `env_file` 注入、离线机由 `.env` 提供；页内值会与之形成两个权威，谁生效取决于进程 → 恰恰是本项目历史上踩过的"配置多处定义"坑。

**收益/成本**：换域名是极低频操作（改一处 `.env` + 重启即可，抓取 / 展示 / CSV 导出 / 中继降级全部跟着走）；页内编辑的收益接近零，却会引入误导（用户以为改了全局生效）与两套权威。

**若要"看得见"（可选的只读回显）**：`GET /api/health` 已返回 `env`（local/docker/linux）、`public_root`（当前展示域名）、`mirror_upstream`（帖子链接中继上游，空=本环境无镜像）。设置页若要加一条**只读**「运行环境」信息行（并注明"改域名请改 `.env` 后重启"），数据取该接口即可，**无需后端改动**——是否添加待用户确认（按通用约束第 20 条，只读信息也要避免与既有位置重复表述）。

**同期（2026-09-17）展示层两处口径变化，与本节相关**：

- **浏览器打开 / 复制帖子链接**经同源中继 `/mirror`（本地镜像只绑回环，手机无法直连；详见《项目结构介绍.md》展示端说明与 `web/mirror.py`）；
- **Web 端导出的 CSV** 的「链接」列改为**相对路径** `/htm_data/...`（与库内、采集端 CSV 同一形态，不带任何域名）：导出物会离开本机，带域名（无论本机镜像还是业务域名）都会在某种环境 / 设备上失效，相对路径由使用者按环境拼前缀最稳（经用户 2026-09-17 确认）。
