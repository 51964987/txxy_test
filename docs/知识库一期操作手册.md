## 二、日常使用：增量沉淀（主线路，开箱即用）

### 1. 配置筛选条件（Web 设置页 → 知识库组）

| 参数                 | 默认    | 说明                                                                                                                                  |
| -------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 启用知识库增量       | 开      | 关闭后定时不再触发                                                                                                                    |
| 知识库时刻           | 23:00   | 每天这些时刻自动跑增量（最多 6 个）                                                                                                   |
| 增量版块筛选（fid）  | 空=不限 | 逗号分隔，如`7` 或 `7,22`；定时与手动按钮同一份筛选                                                                               |
| 增量发布日期范围     | 全部    | 五档枚举：全部 / 今天发布 / 昨天发布 / 近 3 天（含今天）/ 近 7 天（含今天），按帖子发布日（posts.date）圈定；定时与手动按钮同一份筛选 |
| 知识库帖间间隔（秒） | 3       | 抓详情页间隔                                                                                                                          |
| 知识库单批帖数上限   | 3000    | 超限截断余量次日续跑；防积压请保持 ≥ 日均增量 × 2                                                                                   |

**示例**：只沉淀「技术讨论区（fid=7）每天新发的帖」→ 版块筛选填 `7`，「增量发布日期范围」选「今天发布」。

### 2. 手动立即执行（验证参数 / 补跑）

设置页「知识库」组状态区下方点 **「立即执行增量」**：

- 与定时增量**同一入口、同一筛选、同一份状态**（结果写入「上次结果」）
- 后台线程执行，不阻塞页面；上一批未结束、抓取运行中、磁盘水位不足时会被拒绝并提示原因（409）
- 想立即看到结果：执行结束后看「上次结果」，产物在 `outputs/vault/`

### 3. 不想等定时、只想用命令行

```powershell
# 手动跑一次增量（与定时同一入口，应用设置页里的筛选条件）
python -c "import sys; sys.path.insert(0, 'web'); import kb_export; print(kb_export.summarize_reason(kb_export.run_scheduled()))"
```

## 三、按需：全库首建（暂缓，后续要做再看）

> 当前策略**不做全量首建**，增量即开即用（防退化由「单批上限 + 筛选条件」兜底）。
> 未来要全库沉淀时按本节操作，无需改代码。

1. 按**自然月**分片跑（约 22 片：2006~2024 并作 1 片 + 2025-01 起逐月），先 dry-run：

   ```powershell
   python kb_export.py --dry-run --date-from 2025-01-01 --date-to 2025-01-31
   python kb_export.py --date-from 2025-01-01 --date-to 2025-01-31 --skip-concepts
   ```
2. 全部分片跑完后置位标记（幂等）：`python kb_export.py --mark-initial-done`
3. 设置页「首建未完成」的提示会消失；置位不影响增量行为。

注意：首建期间**建议先关闭定时增量**（增量集会被历史积压挤占，单批上限按 date 新帖优先截断，不会阻塞但浪费批次），跑完再打开。

## 四、LLM 概念编译（可选，按预算启用）

LLM 配置（env-only，写项目根 `.env`；缺失时自动跳过 LLM 段，不阻塞笔记落盘）：

| 环境变量              | 说明                                                                                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DEEPSEEK_API_KEY`  | DeepSeek 档密钥（按所选后端拼接读取：`{后端大写}_API_KEY`）                                                                                                             |
| `GLM_API_KEY`       | GLM / 智谱档密钥（同上规则）                                                                                                                                              |
| `CUSTOM_API_KEY`    | 自定义（OpenAI 兼容）档密钥（同上规则）                                                                                                                                   |
| `TXXY_LLM_MODEL`    | 模型名（默认层 env 覆盖；一般用页内「知识库 → LLM 模型名」）                                                                                                             |
| `TXXY_LLM_BASE_URL` | 默认层 env 覆盖；留空 = 跟随后端官方默认（DeepSeek`https://api.deepseek.com/v1` / GLM `https://open.bigmodel.cn/api/paas/v4` / Ollama `http://127.0.0.1:11434/v1`） |
| `TXXY_LLM_PROVIDER` | `deepseek`（默认）/ `glm` / `ollama` / `custom`                                                                                                                   |

> 2026-10-01（修订 37）起：后端 / 模型名 / 接口地址在**参数设置页「知识库」卡**直接配置，切换后端自动回填该后端的地址与模型默认值；密钥仍不进页，按后端从上述环境变量读取（Ollama 无需密钥）。旧 `TXXY_LLM_API_KEY` 口径已废除。
>
> **Ollama 档注意**（2026-10-01）：程序自动走 Ollama 原生 `/api/chat` 并关闭 thinking（`/v1` 兼容端点关不掉思考，content 会恒为空）；模型请选 **≥4B 指令模型**（实测 0.8B 级无法稳定产出合法 JSON，全部帖判「输出非法」）。

补跑 / 重生成：

```powershell
python kb_export.py --regen-concepts incremental   # 只补未判定帖（含 skip/无密钥攒下的待办）
python kb_export.py --regen-concepts               # prompt 改版后全量重生成（禁与筛选参数同用）
```

## 五、常用命令速查

| 场景                                         | 命令                                                                    |
| -------------------------------------------- | ----------------------------------------------------------------------- |
| 看计划不写盘                                 | `python kb_export.py --dry-run --fid 7 --date-from ... --date-to ...` |
| 手动补任意窗口（CLI 筛选，不受页面筛选影响） | `python kb_export.py --date-from ... --date-to ...`                   |
| 源内容疑似变化，重抓重转                     | 加`--force`（可重入永久失败清单）                                     |
| 提取器升级后全量重转（零请求）               | `python kb_export.py --reconvert --skip-concepts`                     |
| kb_state 丢失后恢复断点                      | `python kb_export.py --rebuild-state`                                 |

## 六、产出物在哪

```
outputs/vault/                     # Obsidian 直接打开此目录
├── raw/<版块名>/<标题>.html       # 原始件（按字节存盘；frontmatter original 指向它）
├── wiki/sources/<版块名>/<标题>.md # 笔记（文件名=标题，含资源清单 + See also）
├── wiki/entities/authors/*.md     # 作者实体页
├── wiki/entities/sections/*.md    # 版块实体页
└── wiki/concepts/*.md             # LLM 概念页（启用 LLM 后产出）
outputs/kb_state/                  # 批次状态（断点/失败/磁力索引/concept 索引）——与 vault 成对搬迁
```

- `notes/`、`maps/` 为人工区，程序与 LLM 均不写入
- 全局图谱在该量级下不可用，用**局部图谱展开 + frontmatter 筛选**

## 七、故障排查

| 现象                                   | 处置                                                                                |
| -------------------------------------- | ----------------------------------------------------------------------------------- |
| 点「立即执行增量」提示 409             | 看提示文案：上一批未结束 → 等它完成；抓取运行中 → 等抓取结束；水位不足 → 清磁盘  |
| 上次结果「磁盘水位不足」               | 清理磁盘或调小`precipitate_min_free_gb`（自动下载组）后重试                       |
| 积压只增不减                           | 若「增量发布日期范围」选了窄窗（如仅今天）仍积压，检查单批上限是否 ≥ 日均增量 × 2 |
| 笔记被跳过计数「疑似人工修改」         | 人工改过的笔记不被覆盖；想以程序版覆盖，对该帖加`--force`                         |
| 「疑似人工移动/删除」计数              | 你在 Obsidian 改名/移动过 sources 笔记；想重建请`--reconvert`                     |
| 永久失败 > 0                           | 失败满 3 次的帖不再自动重试；修复原因后用`--force` 重入                           |
| `--reconvert` 被拒绝（恢复重建状态） | kb_state 恢复后 hash 不可重建，首轮须`--force`                                    |
| LLM 段积压 > 0                         | 未配 LLM 键或判定失败积压；配好键后`--regen-concepts incremental` 补跑            |
| Ollama 档 LLM 全部「输出非法」        | 模型能力不足：换 ≥4B 指令模型（0.8B 级实测无法产出合法 JSON）；thinking 已由程序在原生端点自动关闭 |

## 八、换机 / 离线镜像交付

1. **`outputs/vault/` 与 `outputs/kb_state/` 必须成对拷贝**（只拷 vault → 生成 hash 缺失，全部笔记按「疑似人工修改」跳过且 `--reconvert` 被拒）。
2. 新机执行 `pip install -r requirements.txt`，确认 `.env`（访问链 / LLM 键）随迁。
3. 若 kb_state 丢失：`python kb_export.py --rebuild-state` → 按输出提示操作（首轮覆盖用 `--force`）。

## 九、安全红线（记住三条即可）

1. `raw/*.html` 是站点原始页：**不要**让任何 Web 服务把它下发给浏览器；本地查看用文本编辑器（双击 file:// 打开会执行页面外链脚本）。
2. 搜索/图谱的 Web 端（二期）对正文一律纯文本渲染；当前一期无此暴露面。
3. LLM API key 只放 `.env`，不入库、不进参数页。
