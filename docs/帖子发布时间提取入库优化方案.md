# 帖子发布时间（created_at / date）改为从 HTML `data-timestamp` 提取 — 优化方案 v2

> 状态：**已实施完成（2026-08-27 落地）**。后续演进：Header「更新时间」已改用入库活动时间（`/stats/overview` 的 `latest_run_at`，见《数据总览大屏设计与优化总览.md》第九节）；文中 `today_top_fids` / `rising` 接口已分别更名为 `today_fids` / `today_top`。
> 决策结论（2026-08-27 用户确认）：
> 1. `date` 一并改为由发布时间戳派生的真实发布日期（与 `created_at` 同源）；
> 2. upsert 将 `date` / `created_at` 纳入冲突更新（存量自愈）；
> 3. 暂不执行 `--restart` 全量重抓，靠日常增量抓取逐步自愈。

---

## 一、现状与问题

### 1.1 当前入库逻辑（`scraper.py`）

`parse_links()` 目前从每行 `<tr>` 提取 5 个字段：

```
(title, href, likes, author, replies)
```

`save_to_sqlite()` 写入时：
- `date` = 外部传入的 `today_str`（**抓取当天日期**，与列注释「帖子发布日期」名实不符）；
- `created_at` = **首次入库时刻**（ISO 字符串），upsert 时保持不变；
- upsert 的 `ON CONFLICT ... DO UPDATE SET` 不含 `date` 与 `created_at`。

### 1.2 目标

页面 HTML 的作者单元格内已带帖子真实发布时间的时间戳属性：

```html
<div class="f12">
  <span class="s3" title="2026-08-27 今天 12:51" data-timestamp="1787806292s">7 小時</span>
</div>
```

- 属性：`data-timestamp="1787806292s"`（末尾带一个 `s`）
- 期望入库值：`created_at = 1787806292`（Unix 秒十进制字符串）、`date = 2026-08-27`（由该时间戳派生）

## 二、确认后的最终设计

### 2.1 `scraper.py`

1. **`parse_links()` 返回值扩为 6 字段**：`(title, href, likes, author, replies, pub_ts)`
   - 从行内作者单元格的 `<div class="f12">` 下 `<span class="s3">` 取 `data-timestamp`；
   - 去掉尾部 `s` / `S`，校验纯数字后入库；
   - 同一行末楼 `<a class="f10">` 也带 `data-timestamp`（无 `s` 尾缀，是最后回复时间），**必须限定从 `div.f12` 内取**，避免误取回复时间；
   - 属性缺失或非法时回退当前时刻（保证 `date NOT NULL`、`created_at` 非空与排序可用）。

2. **`date` 由发布时间戳同源派生**：
   `datetime.fromtimestamp(int(pub_ts)).strftime('%Y-%m-%d')`（本机时区北京时间，与站点一致）；
   `save_to_sqlite()` 删除外部 `date` 参数，`main()` 中 `today_str` 相关传参移除。

3. **upsert 纳入自愈**：

   ```sql
   ON CONFLICT(title) DO UPDATE SET
       fid=excluded.fid, url=excluded.url,
       likes=excluded.likes, author=excluded.author,
       replies=excluded.replies,
       date=excluded.date, created_at=excluded.created_at,
       update_at=?, update_date=?
   ```

   发布信息是恒定真值，重复写入幂等无害；存量旧数据（ISO 串 / 抓取日）在每次被重新抓到时自动修正为真实发布时间。用 `excluded.*` 引用不增加占位符。

4. **CSV 不新增列**，表头仍为 `[标题, 地址, 点赞数, 作者, 回复数]`；断点续写结构不受影响。

### 2.2 `init_db.py`

- DDL 中 `date` 注释 →「帖子发布日期 YYYY-MM-DD（由 data-timestamp 发布时间戳派生）」；
- `created_at` 注释 →「帖子发布时间戳 Unix 秒（来自 HTML data-timestamp，重复时随重抓修正）」；
- `_SCHEMA_COMMENTS` 对应两条同步；重跑脚本幂等刷新 `schema_comments` 表（旧表 DDL 注释不会重建，以注释表为准）。

### 2.3 下游展示适配

| 位置 | 处理 |
|---|---|
| `web/api.py` | **不改 SQL / 不改接口**：`ORDER BY created_at`、`MAX(created_at)`、表达式索引对 10 位等长整数串字典序 == 数值序，天然正确 |
| `utils/time.ts` | `formatRelativeTime` 兼容双格式（纯数字 ≥9 位视为 Unix 秒）；新增 `formatFullTime`（tooltip 用完整时间）与 `formatShortTime`（HH:MM）导出 |

| `PostsView.vue` | 表格列「抓取时间」→「发布时间」，tooltip 由裸 `row.created_at` 改 `formatFullTime(...)`；排序下拉文案「入库时间倒序/正序」→「发布时间倒序/正序」（value `created_at_desc/asc` 不变） |

## 三、统计口径变化说明（预期内跳变，非 Bug）

以下全部从「按抓取日」变为「按真实发布日」：

- `/api/stats/overview`：today / yesterday / week_new
- `/api/stats/trend`（及 trend_by_fid）：每日柱变为真实「每日发帖趋势」
- `/api/stats/fid_dist`：版块今日/昨日分布
- `/api/stats/top_authors`、`top_fids`、`today_fids`、`today_top`：今日口径同理（注：`today_top_fids`/`rising` 为实施时接口名，现已更名为 `today_fids`/`today_top`）
- Dashboard Header「更新时间」含义从「最后抓取时刻」变为「库内最新发帖时刻」（暂保留现逻辑，如需保留后者概念后续可用 run_days 运行记录展示）

边界特性：

1. 历史柱会随补抓回填增高——数据变准的表现；
2. 爬虫停跑期间的日子柱子就是低的，无法弥补；
3. 存量旧数据在未被重抓前仍是 ISO 串 / 抓取日，展示层已做双格式兼容过渡；
4. 暂不 `--restart` 重抓（用户决策）：自愈只覆盖日常增量能触达的标题，历史部分接受缺失。
