# txxy 数据采集与展示系统 · 设计方案

> 版本：v1.0（对应当前仓库最新代码）
> 说明：本文档依据仓库内实际代码整理，涵盖采集、入库、资源下载与 Web 展示全链路。

---

## 1. 项目概述

### 1.1 目标

构建一套从源站（本地代理 `127.0.0.1:1024` 或指定域名）批量采集版块帖子数据、持久化到 SQLite、并按需下载帖子内媒体资源、最终以 Web 页面进行只读展示的完整工具链。

核心诉求：

- **采集**：多版块并发、断点续抓、请求重试、反爬保护、权限拦截自动停止；
- **入库**：标题去重（upsert）、运行记录可追溯、与展示服务并发安全；
- **展示**：只读 Web 数据总览、帖子检索/筛选/导出、运行记录实时查看、下载资源管理。

### 1.2 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 采集脚本 | Python 3.10+ / requests / BeautifulSoup（标准库 `html.parser`） | 命令行运行，无 Web 依赖 |
| 存储 | SQLite（`db/posts.db`，WAL 模式） | 抓取进程可写、展示进程只读并发 |
| Web 后端 | FastAPI + uvicorn | 只读访问 SQLite，托管前端静态资源 |
| Web 前端 | Vue3 + Vite + TypeScript + Element Plus + Pinia + ECharts | SPA，`/api` 代理调用后端 |
| 自动化 | Windows 计划任务 + `.bat` | 每日定时批量抓取、一键启动 Web |

### 1.3 总体架构与数据流

```
源站（本地代理 127.0.0.1:1024 / 指定域名）
        │
        ▼
┌─────────────────────────────────────────────────┐
│ run_batch.py（多版块并发调度）                     │
│   └── scraper.py ×N（每版块一个子进程，断点续抓）   │
│         ├── outputs/YYYYMMDD/*.csv（列表快照）     │
│         └── db/posts.db（posts 表 upsert）         │
│   └── run_recorder.py（run_days / run_sections 落库）│
└─────────────────────────────────────────────────┘
        │
        ▼
download_files.py（按需下载帖子媒体）
   ├── extract_images / extract_videos / extract_torrents
   │     └── media_download.py（通用下载核心）
   ├── extract_magnets / extract_clouds（TXT 清单）
   └── downloads/<标题>/（gifs/ jpgs/ videos/ magnets.txt clouds.txt）
        │
        ▼
Web 展示（只读）
└── FastAPI（/api/*）
      ├── db.py（PRAGMA query_only 只读 + 60s TTL 缓存 + URL 归一化）
      ├── runs.py（运行记录读取）
      ├── resources.py（downloads 目录扫描）
      └── frontend（Vue3 SPA：数据总览 / 帖子浏览 / 运行记录 / 资源管理）
```

## 3. 数据层设计（SQLite）

### 3.1 数据库文件

- 路径：`db/posts.db`（可通过环境变量 `POSTS_DB` 覆盖）
- 模式：WAL（写进程开启），抓取多进程写入与展示只读并发安全

### 3.2 `posts` 表（帖子主表）

| 列 | 类型 | 说明 |
|---|---|---|
| title | TEXT PK | 帖子标题，主键去重（upsert 依据） |
| fid | TEXT | 版块 ID |
| date | TEXT | 帖子发布日期 YYYY-MM-DD |
| url | TEXT | 帖子链接（入库为公开域名） |
| likes | TEXT | 点赞数（文本数字，可能为空） |
| author | TEXT | 作者昵称（用户/活跃用户统计依据） |
| replies | TEXT | 回复数（文本数字，可能为空） |
| created_at | TEXT | 首次入库时间戳（重复时保持不变） |
| update_at | TEXT | 最近覆盖写入时间戳（首次插入为空） |
| update_date | TEXT | 最近覆盖写入日期 |

- 索引：`idx_posts_fid`、`idx_posts_date`、`idx_posts_fid_date`
- 写入策略：`INSERT ... ON CONFLICT(title) DO UPDATE`，新增与覆盖均计 1 条入库
- 兼容：`init_db.py` 会对旧库自动 `ALTER TABLE` 补列（缺失时为空字符串）

### 3.3 `run_days` / `run_sections`（运行记录）

`run_days`：每次运行一条，`id` 自增主键，同一天多次运行各自成条、历史保留。

| 列 | 说明 |
|---|---|
| run_date | 运行日期 YYYYMMDD（对应 outputs 日期目录） |
| source | run_batch（批量）/ scraper（单跑） |
| status | running / ok / error / cancelled |
| ok / fail / skip | 成功 / 失败 / 未执行版块数 |
| csv / sqlite | 本次 CSV 写入总条数 / SQLite 入库总条数 |
| duration | 总耗时（秒，运行中为空） |
| created_at / updated_at | 创建 / 更新时间戳 |

`run_sections`：通过 `run_id` 关联 `run_days.id` 的版块明细，含 `total_pages / current_page / progress` 三个实时进度字段（running 状态下 Web 端可实时聚合展示）。

### 3.4 `schema_comments`（中文注释表）

- `posts`/`run_days`/`run_sections` 建表 DDL 每列以 `/* */` 标注中文含义（新表随 `sqlite_master` 持久化）；
- `schema_comments` 表（`object_type + table_name + column_name` 主键）幂等保存全部表/列中文注释，旧库重跑 `init_db.py` 即补齐，供数据库工具 / Web 查询字段含义。

### 3.5 只读访问与缓存（web/db.py）

- 使用普通连接 + `PRAGMA query_only = ON`，而非 readonly URI（WAL 模式下 `-shm/-wal` 不存在时 readonly URI 会因无法创建共享内存而失败）；
- 每次查询短连接，避免跨线程复用 sqlite3 连接；
- 60 秒 TTL 内存缓存（`db.cached`）包裹统计接口，避免高频刷新打库；
- URL 归一化：`http://127.0.0.1:1024` 前缀在展示层统一替换为 `PUBLIC_ROOT`，不改数据库。

## 4. 采集层设计

### 4.1 scraper.py（单版块抓取器）

命令行：`python scraper.py <版块ID> [起始页] [结束页] [根地址] [--public <域名>] [--restart]`

- **根地址识别**：`http/https` 开头的数字参数之后的参数自动识别为根地址（位置不限）；`--public` 仅影响入库链接拼接；
- **断点续抓**：进度写入 `*_progress.txt`，重跑从上次完成页码继续；失败页不推进进度，下次重抓防漏；
- **请求重试**：网络异常（连接拒绝/超时）与 `408/429/5xx` 按退避递增重试（第 N 次等待 `RETRY_BASE_DELAY×N` 秒，最多 `REQUEST_MAX_RETRIES=3`）；其它 4xx 确定性失败不重试；
- **连续失败保护**：连续 `MAX_CONSECUTIVE_FAILURES=3` 页失败视为站点不可用，停止抓取避免空转；
- **权限拦截**：检测到页面权限拦截文本立即 `sys.exit(1)`；
- **双写**：每 `BATCH_SIZE` 页刷新 CSV，每 `SQLITE_BATCH_ROWS` 行批量提交 SQLite；
- **机器汇总行**：`__SUMMARY__ fid=.. rows=.. db_rows=.. pages=..`（用 `file_logger.raw()` 包裹不加时间戳，供调度器解析）。

### 4.2 run_batch.py（多版块并发调度）

- 遍历 `SECTIONS`（13 个版块，可扩展），每版块启动独立 `scraper.py` 子进程；
- `MAX_WORKERS=3` 并发、`STAGGER_DELAY=5s` 错峰启动降低反爬风险；
- **1024 端口守护**（`USE_LOCAL_PROXY` 开关，默认开启）：
  - 未监听 → 启动 `web.exe` 并等待就绪（最长 15s），失败终止并提示改用直连域名；
  - 已监听 → 视为外部进程，结束后不关闭；
  - 任务结束关闭自启进程并等待端口释放（最长 10s），`terminate` 失效时按端口定位 PID 强制结束进程树；
- **直连备选**：`python run_batch.py false`（或配置区改 `USE_LOCAL_PROXY=False`），在 `REMOTE_ROOT_URL` 配置实际域名后直接访问；
- **入库链接统一公开域名**：始终以 `--public <REMOTE_ROOT_URL>` 传真实域名，避免库内出现本机不可访问的 `127.0.0.1:1024`；
- 运行结束由 `run_recorder.py` 落库（scraper 子进程通过环境变量 `SCRAPER_RECORD_RUN=0` 关闭重复落库）。

### 4.3 run_recorder.py（运行记录持久化）

- 运行开始创建 `status=running` 记录，运行中实时更新各版块进度，结束更新最终状态；
- 多进程并发写库：各 scraper 子进程持有独立连接，按 `run_id+fid` 更新自己的行，`busy_timeout=15s` 保证写锁竞争安全。

### 4.4 file_logger.py（统一日志）

- 控制台与日志文件双写（`outputs/日期/<程序名>_<日期>.log`，UTF-8 追加）；
- 非空日志自动加 `[时间] [服务名]` 前缀（如 `[scraper_2]`），子进程转发行由调度器实时落盘；
- `with file_logger.raw():` 保持机器行原样（不加时间戳/标签）；
- 过期清理仅由 `run_batch.py` 批次正常结束后触发（保留 3 天），异常退出不清理现场；`download_files.py`/`init_db.py` 等手动脚本不触发清理。

## 5. 资源下载层设计

### 5.1 模块依赖（单向，无循环）

```
extract_images.py ──┐
extract_videos.py ──┼─► media_download.py   # 通用下载核心
extract_torrents.py ┘
extract_magnets.py   # 磁力提取 + TXT 导出（无需网络）
extract_clouds.py    # 云盘中转还原 + TXT 导出（无需网络）
download_files.py ──► 调用各 extract 模块（页面访问 + 下载编排）
```

### 5.2 download_files.py（主流程）

入参必须为 `http(s)://` 完整链接（首个入参若为媒体文件名则仅作下载目录名）。

输出结构：

```
downloads/<帖子标题>/
├── gifs/       # 页面同时存在 gif 与 jpg 时才创建
├── jpgs/
├── videos/     # 仅提取到视频时创建
├── magnets.txt # 磁力清单（UTF-8 含 BOM）
└── clouds.txt  # 云盘清单
```

### 5.3 关键容错策略

| 场景 | 处理 |
|---|---|
| 限流 429 / 5xx / 网络异常 | `fetch_page` 递增重试（最多 3 次），429 尊重 `Retry-After` |
| 图床反广告页（23img.com） | 图片/视频使用纯类型 `Accept`（不含 `text/html`） |
| 403/401/429 / 内容不符 | `download_media` 降级为无 Referer 重试一次 |
| 内容校验 | 按文件头 magic bytes 校验（JPEG/PNG/GIF/WebP/AVIF/SVG、MP4/WebM/FLV），拒绝广告 HTML 存为媒体 |
| 占位图 | 跳过 `adblo_ck`、`blank.gif`、`spacer.gif` 等 |
| 云盘中转占位 | 剔除含 `action=image&url=` 的图片中转链接 |
| 断点续传 | 目标文件已存在且非空即跳过，中断重跑不重复下载 |

## 6. Web 服务层设计（FastAPI）

### 6.1 app.py（服务入口）

- `FastAPI(title="txxy 数据展示")`，`/api/docs` 提供 OpenAPI 调试；
- `/api/health` 健康检查（返回 db 路径、是否存在、public_root、前端是否构建）；
- 若 `frontend/dist` 存在则托管 `/assets` 与 SPA 回退（`index.html`）；否则根路径返回提示 JSON；
- 入口强制 stdout/stderr 为 UTF-8（Windows GBK 控制台兼容兜底）。

### 6.2 配置（web/config.py）

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| POSTS_DB | db/posts.db | 数据库路径 |
| OUTPUTS_DIR | outputs/ | 输出目录 |
| DOWNLOADS_DIR | downloads/ | 下载资源目录 |
| PUBLIC_ROOT | https://txxy.com | 展示层 URL 归一化公开域名 |
| TXXY_WEB_HOST | 127.0.0.1 | 监听地址 |
| TXXY_WEB_PORT | 8088 | 监听端口 |
| TXXY_ENABLE_AUTO_REFRESH | 0（关闭） | 数据总览自动刷新总开关 |

### 6.3 REST 接口清单（web/api.py）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/config | 前端运行时配置（`enable_auto_refresh` 等） |
| GET | /api/stats/overview | 数据总览（累计/今日/昨日/近7日/用户数/点赞榜/回复榜） |
| GET | /api/stats/trend?days=30 | 每日新增趋势（近 N 天，30 天全量返回，前端 7/30/90 切换） |
| GET | /api/stats/fid_dist | 版块分布（含 latest_date / today_count / yesterday_count） |
| GET | /api/stats/recent?limit=10 | 最近抓取 Top10 |
| GET | /api/posts/fid | 版块元信息（fid/name/count/latest_date） |
| GET | /api/posts | 帖子列表（fid 多选/日期区间/关键词/分页/排序） |
| GET | /api/posts/export | 导出 CSV（10 列、UTF-8 BOM，Excel 可直接打开） |
| GET | /api/runs | 运行记录列表（按日期聚合） |
| GET | /api/runs/detail/{run_id} | 按数据库记录 ID 查询明细（优先） |
| GET | /api/runs/{date_str} | 按日期目录查询明细（兼容回退） |
| GET | /api/resources | downloads 目录扫描结果 |

### 6.4 接口设计要点

- **overview 榜单**：`_board_top(field)` 先按版块取该指标最高一条（`ROW_NUMBER() OVER (PARTITION BY fid ORDER BY CAST(field AS INTEGER) DESC, ...)`），再整体 `ORDER BY CAST(value AS INTEGER) DESC` 保证排行榜按指标值严格降序；
- **fid_dist**：近 30 天数据 + `latest_date`（版块最近抓取日期）、`today_count`、`yesterday_count` 供前端展示副指标；
- **缓存**：统计接口用 `db.cached("overview")` / `db.cached("fid_dist_v2")` 等 60s TTL 缓存；
- **只读安全**：所有查询经 `db.query`（`PRAGMA query_only=ON`），绝不写库。

## 7. 前端设计（Vue3 SPA）

### 7.1 工程与依赖

- Vite + Vue3 `<script setup>` + TypeScript；
- Element Plus（zh-cn locale，全部图标全局注册）；
- Pinia（`stores/dashboard.ts` 共享全局状态）；
- ECharts（趋势折线 / 版块环形图）；
- 路由：`createWebHistory`，四个页面。

### 7.2 页面路由

| 路由 | 页面 | 说明 |
|---|---|---|
| / | 数据总览 | KPI 卡片、趋势、版块分布、热门榜、最近抓取 |
| /posts | 帖子浏览 | 筛选/排序/分页/导出 |
| /runs | 运行记录 | 每次运行一条，实时进度 |
| /resources | 资源管理 | downloads 目录文件清单 |

### 7.3 全局状态（stores/dashboard.ts）

| 状态/方法 | 说明 |
|---|---|
| enableAutoRefresh | 自动刷新总开关（来自后端 /api/config，默认关闭） |
| autoRefresh | 自动刷新开关（30s 轮询开关） |
| refreshing | 手动刷新中 loading 状态 |
| updatedAtText | 最后更新时间文案 |
| setEnableAutoRefresh / setAutoRefresh | 配置下发与开关切换 |
| registerRefresh / triggerRefresh | 页面注册刷新处理器 / Header 触发刷新 |
| setUpdatedAt | 更新时间写入 |

设计要点：Header 与 Dashboard 页面解耦，Header 只负责展示与触发，轮询逻辑由 DashboardView 持有（`setInterval(load, 30000)`），通过 `registerRefresh / registerAutoChange` 回调桥接。

### 7.4 页面详述

#### 7.4.1 数据总览（DashboardView.vue）

- **顶部 Header（全局 AppLayout）**：左侧更新时间；右侧"自动刷新"卡片——仅当 `enableAutoRefresh` 为真时显示开关，否则只显示"刷新"按钮（手动刷新始终可用）；
- **KPI 卡片**：累计帖数、今日新增、昨日新增、近 7 日新增、累计用户、活跃用户，副指标展示环比/今日新增；
- **每日新增趋势**：折线图（渐变面积 + markPoint 峰值），Y 轴取整，7/30/90 天切换，90 天启用 dataZoom；
- **版块分布**：双视图（环形图 / HTML 排行榜），环形图外部标签按占比过滤（≥4% 显示）、扇区/图例点击跳转帖子浏览并按版块预筛选、悬停显示中心动态（最近抓取/今日/昨日）；排行榜行为可点击，标题 tooltip 展示副指标；
- **热门榜**：点赞最高帖 / 回复最高帖左右 1:1 等宽，按指标值严格降序展示序号 1~N；
- **最近抓取**：Top10 列表，序号列 + 相对时间；
- **布局**：`chart-row`（趋势 + 版块分布）`1fr 1fr`、`board-row`（两个热门榜）`1fr 1fr`，间距统一 16px；`<1439px` 统计卡 3 列、`<1023px` 2 列、`<1100px` 图表单列；
- **轮询**：`autoRefresh` 开启时 30s 静默刷新；页面卸载清理定时器并注销回调。

#### 7.4.2 帖子浏览（PostsView.vue）

- 筛选：版块多选（默认全部）、日期区间、标题关键词；
- 排序：日期 / 入库 / 点赞 / 回复（升/降序切换）；
- 分页：服务端分页（page / page_size）；
- 表格：标题（跳转原帖）、版块、点赞、作者、回复；操作栏图标按钮（打开 / 复制链接，悬浮提示）；
- 导出：按当前筛选条件一键导出 CSV（10 列、UTF-8 BOM）；
- 支持 URL 预选版块（从数据总览点击版块跳转，`route.query.fid` 自动选中）。

#### 7.4.3 运行记录（RunsView.vue）

- 数据源：`run_days` / `run_sections`（优先），无 DB 记录时回退解析 `outputs/` 日志；
- 列表：每次运行一条，日期 + 时间合并一列，显示来源 / 状态 / 成功失败未执行数 / CSV 与 SQLite 条数 / 耗时；
- 分页：每页 10 条，`total, prev, pager, next, jumper`；记录数 ≤10 时不显示分页器；
- 实时性：进入页面后固定 4s 轮询刷新（含无 running 状态时），running 行显示实时进度百分比；
- 明细：点击展开查看各版块成功/失败/CSV/SQLite/耗时/页数进度。

#### 7.4.4 资源管理（ResourcesView.vue）

- 扫描 `downloads/` 目录，按文件夹分组展示文件清单（分类图标、大小、路径）；
- 复制路径、总量统计（文件夹数 / 文件数 / 总大小）；
- 文件分类：image / video / torrent / text / other（按扩展名）。

## 8. 构建与部署

### 8.1 Web 服务

```bash
start_web.bat                      # 一键启动（未构建时自动 npm install + npm run build）
# 或手动：
pip install -r requirements.txt
python -X utf8 web/app.py          # 默认 http://127.0.0.1:8088
```

### 8.2 前端构建

```bash
cd web/frontend
npm run build                      # 产物输出到 dist/，由 FastAPI 托管
npm run dev                        # 开发模式（5173，/api 代理到 8088）
```

### 8.3 定时任务

计划任务 `txxy_daily_batch`（每天 01:00，SYSTEM 身份）→ `run_daily.bat` → `python run_batch.py`。

```bash
schtasks /Query /TN "txxy_daily_batch" /V /FO LIST   # 查看
schtasks /Run /TN "txxy_daily_batch"                 # 手动触发
schtasks /Delete /TN "txxy_daily_batch" /F           # 删除
```

### 8.4 服务重启流程（开发期）

1. `cd web/frontend && npm run build`
2. 停止旧进程：`powershell -Command 'Get-NetTCPConnection -LocalPort 8088 -State Listen ... | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }'`
3. 启动新进程（PowerShell `Start-Process` + `-X utf8 app.py`）
4. 健康检查：`curl.exe -s -o NUL -w '%{http_code}' http://127.0.0.1:8088/`

## 10. 已知约定与注意事项

1. **只读安全**：Web 端永不写库；如需写入需走采集脚本链路；
2. **入库量口径**：`db_rows` 为本次实际写入条数（新增+覆盖），非累计总量（查询 `SELECT COUNT(*) FROM posts`）；
3. **URL 展示归一化**：仅展示层替换 `127.0.0.1:1024` 前缀，数据库原始内容不改；
4. **排行榜排序**：热门榜按指标数值（`CAST AS INTEGER`）严格降序，避免字符串字典序错误；
5. **ECharts 窄卡片**：版块分布排行榜采用纯 HTML 渲染（ECharts 横向 bar 在窄卡片下异常）；
6. **Windows 编码**：所有 Python 命令建议带 `-X utf8`，避免 GBK 控制台中文乱码。
